## 2. 本稿的统一建议

采用Vue电脑网页与FastAPI模块化单体，PostgreSQL保存订单、余额、工单、任务、消息、审计、检查点及向量；进程职责可分离，业务模块不拆成微服务。使用受控业务服务完成写入，LangGraph负责流程和中断。模型仅提出候选与组织回答，不决定身份、权限或退款审批。真实服务接入和运行验证在后续实施阶段进行。

本项目已批准采用Vue Router、Pinia、Element Plus、SQLAlchemy、Alembic及PostgreSQL检查点；中文分词和SQL AST校验采用jieba与SQLGlot。配套由本次设计签核采纳，不回写成需求阶段早已批准；具体兼容版本后续验证。Redis、MQ、Celery、独立RAG平台和多服务拆分不作为默认依赖。

客服对话模型的供应商、具体型号、服务修订及部署资源保留为接入决策，先固定能力契约。Embedding沿用BGE-M3稠密1024维，重排沿用Qwen3-Reranker-0.6B。SQL仅消费可配置API，其型号、微调及服务供给归03；不在01指定SQL基线型号。
