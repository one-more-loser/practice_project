# 数据与状态设计

版本：DESIGN-CS-v0.1；依据REQ-CS-v0.2。逻辑数据/约束/事务设计已获用户批准；本文保持逻辑基线，后续B0的身份/来源/受控输入/审计物理映射、迁移与局部证据见[实施记录](../04-implementation/README.md)。其余域随对应任务增量建立，不能从本设计表推定已建表。

## 1. 字典约定与权限分级

所有实体标明主键、店铺/主体归属和来源；关联使用稳定业务ID，不能以姓名/手机号/订单展示号关联身份。普通实体共用created_at、updated_at、version、source_kind、data_batch_id；事件/流水另有occurred_at与recorded_at。必填字段不能为空，条件字段仅在业务发生时必填，未发生时间/结果留空，不用0或当前时间伪造事实。

| 字段类别 | 逻辑类型、单位及语义 | 空值/来源/权限 |
| --- | --- | --- |
| *_id、*_ref | 不透明标识/受控引用；外部标识另存external_id与source_system | 创建后必填且稳定；跨项目映射未对齐不得猜关联；标识本身不是访问凭证 |
| *_qty、sequence、version | 非负整数；业务选择数量为正整数；version单调递增，sequence在所属流内递增 | 发生后必填；由服务端核算；不能用前端/模型覆盖 |
| *_minor | CNY分，精确整数；API以十进制整数字符串传递 | 金额发生后必填，0是已知零额而非未知；拒绝浮点/超出可表示范围，不虚构业务充值上限 |
| *_at、valid_from/to | 带时区的时间点；API采用ISO 8601，内部统一时间点计算，业务解释Asia/Shanghai | 创建/发生时间来自服务端或标记的模拟来源；来源未给时间不能补当前时间；有效区间开始含/结束不含 |
| status、type、reason_code | 有定义的枚举/原因；本文状态语义见第4节 | 必填，未知外部枚举记契约错误/待映射，不静默转成功 |
| policy/schema/model/contract/index_revision | 不可变版本引用/内容指纹 | 对应判断/调用发生时必填，未知版本拒绝或明确降级 |
| source_kind、data_batch_id | synthetic/business_import/derived等来源及隔离批次 | V1样本全为synthetic；真实CSV补充字段分别记录，不混同原字段 |
| sensitivity/visibility | public、self_business、assigned_support、store_service、knowledge_internal、restricted_pii、secret | 字段投影独立于实体可见；secret只配置引用；restricted_pii仅本人受控页面/业务处理可读 |

下节“必填”继承上述共用字段；仅事件使用发生/记录时间替代普通更新时间。审计记录脱敏差异或快照引用，不存完整地址/电话。完整收货快照与模型/支持视图分离：员工电话只末四位、地址只到市；顾客本人个人页专用读取可以取完整值。

## 2. 逻辑实体与关系

### 2.1 身份、商品和结算

| 实体/粒度与键 | 必填字段与定义 | 条件字段/来源/权限及约束 |
| --- | --- | --- |
| Store：一家模拟店铺，store_id | name、status、currency=CNY、business_timezone | 外部映射；V1单店不省store_id，不扩展多租户产品 |
| Subject/Customer：登录主体与业务顾客，subject_id/customer_id | subject_type、account_status、customer映射、store_id | 登录名/密码摘要属于身份域，不给模型；开户余额初值0，停用影响新请求和恢复 |
| StaffRoleGrant：员工一次角色授权，grant_id | staff_id、store_id、role、grant_status、grant_version | 有效起止/撤销人原因；兼任角色逐次记录，不隐式合并全部权限 |
| Session：一次受控登录/游客会话，session_id | subject或guest主体引用、状态、expires_at、authorization_version | 退出/吊销时间；仅存会话密钥摘要/安全引用，不在检查点保存Cookie；游客无个人业务查询权 |
| Product/SKU：款式与可售规格，product_id/sku_id | 商品名称/类目/描述/上架；SKU规格键值、单价minor、币种、可售状态、price_version | 商品资料/公开图片引用、别名、外部SKU；内部成本不进公开/客服顾客模型面；价格来自店铺业务维护 |
| Inventory：SKU可售账面存量，sku_id | stock_qty、reserved_qty、version；available_qty=stock_qty-reserved_qty | stock_qty不是仓库实物盘点；必须stock_qty≥reserved_qty≥0，公开只读available_qty与as_of |
| Reservation/StockMovement：订单预留及一次变更，reservation_id/movement_id | order_id、sku_id、qty、类型/状态、来源业务ID、操作者、发生/记录时间 | 预留expires_at/消耗/释放；库存变更留前后值/原因；同业务效果唯一，员工不能无依据改历史流水 |
| Cart/CartItem：本人购物车及SKU行，cart_id/cart_item_id | owner、store、SKU、正整数qty、selected、version | 展示缓存价非权威；失效/缺货/变价提示；不能把购物车修改等同库存预留 |
| Quote/QuoteLine：一次结算候选，quote_id/line_id | 本人、SKU/数量、名称规格/单价、优惠/商品实付分摊、运费、应付、currency、报价版本/有效期、适用政策版本 | 失效原因；报价过期或价格/库存变化必须重展示确认，不允许前端提交任意总额；不新增促销引擎 |

## 3. 金额、数量与库存口径

订单应付=各行商品原额－优惠合计＋原运费；原实付仅由成功支付形成，累计成功退款分开保存。净实付=原实付－累计成功退款；订单级应付/实付不能在明细连接后重复相加。退款分商品与原运费，普通退货原运费不退，质量/错发及运输异常按已核验适用政策；政策缺失不由模型猜额。

全部商品退货或全部申请结清，不等于原实付全额退回。例如商品实付10000分、原运费1000分，普通全部退货只退10000，净实付仍1000；应显示“商品退货退款完成，原运费未退”和实际量额，不能标“原实付全额退款”。剩余净实付也不自动变成可退运费，仍受适用政策约束。

优惠按确定规则分摊到订单行并保存版本；同一行商品实付以分计。行实付10000分、数量3时，建议保存单位分摊[3333,3333,3334]，按尚未消费的单位序号选择；退第一件3333，退剩余两件6667，累计10000。申请拒绝释放对应单位，不因重试重新分摊，最后全部结清尾差。单位序号是逻辑分摊依据，不要求每件商品物理建一行。

可退数量=原数量－成功已退数量－有效处理中占用数量；可退商品额=原行商品实付－成功商品退款－有效占用商品额，运费另在订单级占用。申请/审核/核验/执行均检查剩余量额；失败执行保留仍有效的申请占用等待核对/重试，只有确定拒绝/撤销/结清才释放。禁止通过修改申请数额替代原申请版本与顾客确认。

库存建议在下单预留，余额支付时消耗预留并扣减stock_qty；发货不重复扣库存。未付取消/超时释放预留；已付未发货取消成功回补对应未履约库存；退货核验的实际可售量才回补。丢件退款不凭退款状态增加库存。管理员减库存不能使stock_qty低于已预留，所有变化有来源和唯一变更标识。

| 本人可见订单 | 待付款/待发货/运输中/已收货及售后处理中/部分退款/退款关闭 | 来自交易、履约、售后三个维度投影，不能用一个status丢失事实；终态不接受新支付/发货/改址 |
| 普通取消 | requested→awaiting_confirmation→agent_review→eligible/rejected/needs_human→executed | 仅paid+unshipped可走退款取消，未付关闭不退款；不确定人工补事实再审；执行时发货先成功则拒绝 |

| 运输异常 | open→verifying→awaiting_intercept/awaiting_liability→verified_return/verified_loss→refund_reviewed→refunding/refunded | 无receipt、正式售后关闭；顾客确认、分派审核、退回或责任核验缺一不可；拦截失败不能当退回 |

## 5. 事务、确认与竞争设计

所有下述步骤是设计语义，不是已实现的SQL。外部模型/检索/人工等待均在业务事务外；最终写入使用短事务复核。需要锁定的对象按统一顺序：任务栅栏（如适用）→会话门槛（如适用）→工单/分派（如适用）→订单→SKU→申请/额度→余额账户→动作结果；同域多对象按稳定ID排序，不涉及的对象跳过。不能持有工单锁再反向申请会话锁。幂等接收/租约领取用独立短事务，不跨模型调用持锁。事务冲突有限重试，重试必须使用原operation并复查状态，不重跑模型创建新意图。

任务副作用提交先锁栅栏记录并核验当前代次，重新领取任务也更新同一记录；旧代次不能在新领用之后提交。该门槛与会话epoch、业务状态复核和效果写入保持同一短事务，避免只在模型调用前检查租约。接管通过会话epoch使旧任务失效，不在持会话锁时反向锁任务栅栏。

| 场景 | 同一事务必须完成 | 防重与竞争判定 |
| --- | --- | --- |
| 下单 | 校验本人确认/报价/价格/库存，保存订单/行/地址与政策快照、库存预留、动作结果和事件/审计 | 同operation同结果；变价不静默下单；预留不足拒绝，不负库存 |
| 余额支付 | 锁订单→库存→本人账户，检查待付/预留未过期/余额足够，扣余额、唯一付款流水、消耗预留/库存、标paid、保存事件/结果 | 与超时关闭同订单锁串行；关闭先成功则付款拒绝；付款先成功则超时不再释放 |
| 模拟充值 | 可信本人、合法正金额，锁本人账户，增加等额余额、Topup成功、唯一流水/结果/审计 | 点击提交即确认，不增加审批；同幂等键异参数409，同请求跨24小时不再次入账 |
| 普通取消 | 顾客确认及Agent审核在事务外形成不可变引用；事务内校验当前owner、确认/事实版本、paid/unshipped、退款上限，取消、回补未履约库存、退款/入账一次、事件/审计 | 发货先提交拒绝取消；取消先提交拒绝发货；无有效Agent通过不执行，人工不能旁路 |
| 一次改址 | 锁会话门槛（如适用）及订单，校验有效未发货/count=0/确认/快照归属，换受控快照、count=1、成功Change及结果/事件 | 发货先成功拒绝；改址先成功发货用新快照；响应丢失查原Change，不以超时恢复count |
| 发货/本人收货 | 店铺发货核对本店角色、paid/unshipped及整单明细，写唯一发货事实+in_transit；本人确认核对owner/in_transit，写receipt并推进履约 | 承运轨迹不得调用本人收货命令；并发重复按钮只产生一个业务事件；发货事务提交是改址截止点 |
| 售后申请/审核 | 锁订单及明细额度，校验receipt/政策时间、计算并占用可退单位/量额；顾客确认绑定本次计算；分派客服记录审核依据 | 并发申请不可重复占用；拒绝/撤销原子释放；金额/数量变化要求新确认和版本 |
| 核验收退/退款 | 店铺核验记录实收/可售量和证据；满足审批、收退或主管有效例外后，退款事务锁订单/申请→账户，校验剩余、唯一入账并将占用转成功已退 | 收退数量不符先争议，不按申报全部退；退库与退款分别有来源/幂等，不因重复核验多加库存 |
| 运输异常退款 | 复核顾客确认、分派审核/主管例外、退回/丢件责任证据和适用政策，固定本人账户，唯一退款/流水/事件 | 不能复用正式售后receipt绕过；无可核验金额或运费依据保持待核验，不由模型填任意金额 |
| 排队/人工接管/结束 | 锁Conversation和当前分派关系，改变mode/epoch、撤销旧输出/动作资格，保存模式事件 | 与Agent提交争用同一门槛；断线不结束，结束自动agent且旧确认不恢复 |

确认5分钟是授权有效期，不是资金效果寿命。operation具有主体/动作/规范化参数摘要及原始业务结果；请求结果至少24小时可直接核对，业务唯一关联随业务记录保留。窗口后无法提供原结果时明确拒绝/引导核对，不自动换键。账户总余额=开户0＋成功充值－成功支付＋成功退款；逐条balance_before/after相连，订单已退/申请占用与流水独立可对账。

业务成功但检查点/投递失败：先查operation和业务流水返回原事实，再补消息/任务进度；不反向撤销成功资金。数据库事务未提交则无成功业务效果；重试需当前确认与状态仍合法。直接个人页动作可在人工服务期间由顾客执行，Agent来源动作则受会话模式栅栏限制，两者来源不能伪装。

## 6. 保留、结构演进与失效

沿用已批准保留规则：脱敏会话30日、审计90日，自记录发生时间计；聚合180日自窗口结束计。受控完整收货快照及合成订单/资金流水随隔离演示批次保留/重置，重置需整体保持引用一致并使可达副本不可读，不运行中单删流水或改余额。检查点/派生案例不能保留完整PII，过期内容被清理后旧引用返回已不可用，不用缓存复活。

演示批次重置同时撤销旧会话/任务租约/确认和事件游标，新批次有新的可信代次/对象ID；旧请求不得被当作新批次充值/退款重放。幂等与授权上下文绑定可信批次代次，而非接受客户端自行选择批次绕过去重。

后续采用迁移工具前先逐流程核验数据字典、状态和样本，再设计物理字段/约束/索引/RLS。空库迁移、历史数据升级、回填和回退/前滚均需单独证据；涉及流水和退款额度的破坏性迁移不得只凭自动生成接受。当前不创建ORM模型、DDL或迁移。

知识新版本先校验来源/范围、生成词元和BGE-M3向量、构建完整索引版本，再原子切换发布指针；源停用/过期和撤权在每次读取时检查，索引未刷新也不能继续使用。Embedding模型/维度变化建新完整版本，不能混放1024维与其他维度。FAQ答案缓存键至少含范围、来源/FAQ版本与有效性，不能缓存个人动态业务结果。
