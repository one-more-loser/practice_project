# 跨项目契约草案

版本：XCS-v0.1；2026-10-22。输入REQ-CS-v0.2已批准。**以下仅是01提出的消费/生产契约，未获02、03或总会话共同批准，不代表兄弟项目已实现。** 本轮没有写入其他目录、发送其他会话消息或运行联调。

## 1. 权威事实、ID与归属

| 项目/能力 | 负责生产与消费 | 不负责 |
| --- | --- | --- |
| 01客服 | 模拟商城交易/履约、顾客身份与本人范围、工单/人工协同、知识/FAQ/经验；生产脱敏客服聚合，消费SQL生成API | 促销决策/执行中台、SQL型号选择/训练、独立RAG平台 |
| 02运营 | 消费获准经营数据和客服聚合，分析、促销候选/情景；提出数据/指标消费需求 | 不能凭分析结果直接写01售价/库存/工单/余额，不能据主题共现宣称根因 |
| 03SQL微调 | SQL模型选型、数据/标注/基线/微调/独立评测及服务供给契约 | 不拥有01业务数据库执行权、顾客身份、订单/支付/退款权威，不承担客服工具调用 |
| 总体协调 | 对齐店铺/商品/SKU/订单核心ID、指标定义、Schema/事件版本、权限与真实联调计划 | 单方文档不使对方功能变为已批准 |

## 2. 01→02客服聚合与反馈事件

### 2.1 数据与测量口径

建议01生成带版本的聚合快照，由受控导出或服务身份读取，供02做热点/缺口/投诉和人工介入分析。首次可用固定批次替身消费验证；真实02消费单独验收。

| 字段 | 语义/约束 |
| --- | --- |
| snapshot_id、revision、contract_version | 快照稳定ID、递增修订、XCS-SUPPORT-v0.1；修订替代原快照，不叠加成新咨询量 |
| store_id、window_start/end、timezone | 本店、开始含结束不含、Asia/Shanghai；事件迟到重算产生新revision |
| data_batch_id、source_kind、generated_at | 生成来源、synthetic标记和时间；合成数据不能冒充真实客户运营证据 |
| dimensions | topic_code/product_category；代码版本需对齐，不导出顾客/订单/会话ID |
| metrics | distinct已接收顾客消息数、distinct工单数、投诉工单数、知识缺口数、人工接管会话数，分别注明单位/分母 |
| suppression、completeness | 单主题样本<5抑制、延迟/缺失/修订标记、总分项差异解释；不能删标记后当完整事实 |
| metric_revision、lineage_digest | 固定口径和来源集合指纹供审计；不包含会话原文/内部备注或个人记录清单 |

咨询按去重顾客message_id计，流片段不增加咨询数；工单按ticket_id，投诉按被标记投诉的工单；知识缺口排除单纯工具故障，人工接管按会话维度声明计数周期。多主题可以重叠，必须标明“非可加总维度”和分母，不能把所有主题相加当总咨询量。

样本<5的单元count=null并标suppressed，若总计和其他单元可以反推出被抑制单元，对相关合计/分项二次抑制或不输出，保留差异说明。此为保护既有聚合边界的设计措施，不能以演示样本少为由下发明细。02不能请求个人对话/订单以“补全”统计；更细经营事实消费需另审共同契约，不通过客服反馈偷偷扩大。

```json
  "snapshot_id": "support_snapshot_sim_01",
  "revision": 1,
  "store_id": "store_sim_01",
  "window_start": "2026-10-21T00:00:00+08:00",
  "window_end": "2026-10-22T00:00:00+08:00",
  "timezone": "Asia/Shanghai",
  "source_kind": "synthetic",
  "data_batch_id": "support_eval_sim_01",
  "metric_revision": "CS-METRIC-v0.1",
  "cells": [
    {"topic_code": "delivery_delay", "metric": "customer_message_count", "count": 12, "suppressed": false},
    {"topic_code": "refund_dispute", "metric": "complaint_ticket_count", "count": null, "suppressed": true}
  ],
  "completeness": {"status": "complete_for_declared_batch", "non_additive_dimensions": ["topic_code"]}
}
```

数值为合成示例，不是当前运营结果。topic_code是候选字典，不认定02已支持。

### 2.2 API/事件草案与权限

建议服务身份能力`support_aggregate.read`，限本店/窗口和聚合字段；草案路径GET `/integration/v1/support-summaries`及`/{snapshot_id}`，受控导出采用同一投影。认证密钥/服务令牌仅在后端，调用与导出记审计；过期/越店/未知版本拒绝，不回退到顾客接口。

事件`support_summary.ready`或`.corrected`包含event_id、contract_version、snapshot_id/revision、supersedes_revision、source/occurred_at/recorded_at及聚合引用。Outbox在快照提交时一并保存；读取/投递至少一次，02以consumer_id＋event_id去重，以snapshot_id/revision更新快照。修订事件不能被当新增业务计数；时间窗口/口径变更需显式修订版本。

重试只针对传输/暂不可用，未知契约进待处理/告警，不丢事件并伪装成功；01记录交付状态不等于02已用于分析。02不通过该身份执行客服写动作。商品/库存变更可另提出只读快照或事件，但谁提供全组合经营事实需总协调，本稿不批准订单明细共享。

## 3. 01→03 SQL生成API消费要求

### 3.1 输入与身份隔离

接口职责为“生成候选”，不得执行数据库。03可以提供聊天式兼容API，01在适配层转为以下统一对象；协议路径/认证/模型标识由服务供给方声明并共同确认。**不在01选SQL基线或微调型号。** 03未就绪时可配置可用基线API测试01链路，记录来源与服务版本；替身不等于真实模型，微调完成不作为V1前置。

| 输入 | 必需含义 |
| --- | --- |
| request_id、contract_version | 去重/追踪标识，XCS-SQL-v0.1；不允许用请求ID推断顾客权限 |
| question、context | 去身份化诉求和已确认槽位、业务时间窗/参考时钟；不发完整电话地址、真实身份、会话原文全集或订单结果集 |
| dialect、consumer_profile | PostgreSQL、customer_self/public；员工任意问数不在此能力范围 |
| schema_revision/digest | 允许的逻辑视图/字段/类型/枚举/关联及含义；不是所有物理Schema/系统目录 |
| metric_revision/definitions | 原实付/已退/净实付、订单/明细粒度、时间区间、状态及单位 |
| parameters | 后端已解析的允许参数名/类型及资源令牌说明；模型不提供customer_id/授权条件作为可信身份 |
| limits/capabilities | 最大行数/结构预算，允许query/clarify/unsupported/error；服务修订和响应格式声明 |

```json
{
  "contract_version": "XCS-SQL-v0.1",
  "request_id": "sql_req_sim_01",
  "question": "列出指定时间窗口内本人已付款未发货订单",
  "dialect": "postgresql",
  "consumer_profile": "customer_self",
  "schema_revision": "CS-QUERY-v0.1",
  "metric_revision": "CS-METRIC-v0.1",
  "resources": [
    {"name": "cs_order_self", "columns": ["order_id", "created_at", "trade_status", "fulfillment_status", "original_paid_minor"], "grain": "order"}
  ],
  "parameters": {"start_at": "timestamp_with_timezone", "end_at": "timestamp_with_timezone", "row_limit": "positive_integer_max_50"},
  "limits": {"max_rows": 50, "read_only": true}
}
```

本例资源是逻辑模型面，未创建数据库视图。真实参数值保留在01绑定，可信本人范围由01在独立只读事务/RLS设置，不能依赖候选WHERE。资源令牌在01解析且验证归属，03无需获取实际顾客或订单隐私。

### 3.2 输出与错误

```json
{
  "contract_version": "XCS-SQL-v0.1",
  "request_id": "sql_req_sim_01",
  "kind": "query",
  "schema_revision": "CS-QUERY-v0.1",
  "metric_revision": "CS-METRIC-v0.1",
  "sql": "SELECT order_id, original_paid_minor FROM cs_order_self WHERE created_at >= :start_at AND created_at < :end_at AND trade_status = 'paid' AND fulfillment_status = 'unshipped' ORDER BY created_at DESC LIMIT :row_limit",
  "parameter_names": ["start_at", "end_at", "row_limit"],
  "service": {"model_identifier": "provided_by_03", "revision": "declared-by-provider"}
}
```

候选不是已执行结果，也不携带数据库连接或权限承诺。kind=clarify返回缺失槽位/获准选项类型，不返回他人候选；unsupported声明超出支持范围；error含错误类别/是否可重试/服务修订，不回传密钥或内部栈。格式缺字段、SQL与kind冲突、参数未知、版本错或非单条只读结构均由01拒绝。

01仍完整执行AST/白名单/资源成本/独立身份/字段脱敏/RLS/只读/2秒/最多50行校验；03“已校验”字段不能跳过任何防线。模型不需承担客服工具调用，不要求SQL API支持主对话同样的流式或工具协议。

### 3.3 版本替换与评测归属

03负责模型选型/数据和独立SQL评测，01负责其当前Schema/口径下的业务与越权验收。训练数据、客服验收集、案例归纳和Skill回归集分开版本/用途；01不以真实客户数据自动提供训练授权，截图CSV也不作为既有SQL标签。

替换API时先核验协议、Schema/指标/错误及能力，再用固定80个获准SQL问题和至少40反例回归；比较执行结果语义，不比较SQL字符串相同，不用03独立分数替代01验收。服务或Schema不兼容时明确拒绝/回退已获准版本，不能悄悄继续执行旧语义候选。

## 4. 共同事件、错误与对齐清单

共同事件至少含唯一event_id、contract_version、source_system、store_id、occurred_at、recorded_at、数据批次和资源/快照版本。投递/消费可重放，不能把网络ACK说成业务执行或消费完成。敏感正文不进入跨项目通道。

共同错误区分unauthenticated、forbidden、invalid_input、not_found、unsupported_version、contract_error、timeout、unavailable和rate_limited；是否可重试还需考虑原业务幂等性，安全/权限拒绝不得不断重试。

| 待共同确认 | 01提案/完成条件 | 当前状态 |
| --- | --- | --- |
| 核心ID/权威数据 | 映射店铺/SKU/订单与来源系统，确认只读业务事实提供方和消费范围 | 草案；总目录/兄弟项目未改 |
| 客服指标/抑制 | 确认计数粒度、窗口/重算、多主题非可加总、二次抑制及修订消费 | 01可先用合成替身验证；真实02待联调 |
| SQL模型面 | 逻辑视图字段/枚举/关联、方言/参数、口径/Schema版本及不兼容处理 | 01消费要求；03尚未签收或实现声明 |
| 服务接入 | base_url、认证引用、服务/模型标识、协议修订、能力/超时/限额 | 待服务供给；01不代选SQL型号或部署 |
| 集成证据 | 双方实际版本、接口样本、成功/错误/越权/重放、真实运行与限制 | 当前无联调结果，不能标完成 |
