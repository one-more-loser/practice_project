## 2. 启停与本机连接

已部署实例在Debian执行：

```bash
cd /home/zzh/ecommerce-customer-service-db
docker compose config --quiet
docker compose up -d --wait --wait-timeout 90
docker compose ps
```

需要停机维护时在同一目录执行`docker compose stop`；重新启动执行上述`up`。`unless-stopped`已配置，容器重建持久性已验证；没有执行VM重启验收。不要在旧目录`~/ecommerce-deploy`执行本项目命令，不使用`down -v`或全局资源清理。

本机后端启动方式不变，在本项目根目录的PowerShell执行：

```powershell
$env:CS_DATABASE_PROFILE = 'debian'
& backend/.venv/Scripts/python.exe scripts/serve_local.py
```

后端只监听`127.0.0.1:8000`。另开PowerShell启动前端：

### 配置与隔离

- `.runtime/debian.env`保存远程应用/迁移/测试URL，`.runtime/isolation-debian.json`保存目标清单；口令不进入Compose正文、前端、模型、日志或报告。数据库口令与SSH口令独立。
- 配置优先级：显式profile参数 → `CS_DATABASE_PROFILE` → `.runtime/active-database.json` → 未配置时默认`local`。已选择的profile缺文件则拒绝，不自动回落旧库。直接启动`uvicorn`不会替代配置加载，使用`serve_local.py`入口。
- 应用与迁移均核对项目根目录、角色、主机/客户端端口、库名白名单、PG实际端口、非超级/非BYPASSRLS和实例标识；迁移另核对实际数据目录。远程连接端口55432与PG内部5432分别核对。
- 原`.runtime/local.env`、`isolation.json`和`pgdata`保留。`scripts/check.ps1`固定验证Windows本机库，并隔离/恢复调用者的数据库环境变量；**不是Debian验证脚本**，也不会切换active文件。旧源库是迁移时点副本，不自动合并后续远程交易。

迁移命令已支持`--profile debian`，但本次目标已在最新Schema，无需为启动重复迁移。后续迁移前先备份、核对目标，不手工修改历史迁移或重建业务表。

## 4. 新环境初始化与本次避坑

remote `secrets/`目录700，文件444，`backups/`700；挂载的secret须可被容器PG用户读取。Compose文件secret是宿主机文件挂载，不能依赖本地文件挂载未兑现的uid/gid/mode声明。SSH临时认证文件收尾删除，已记录主机密钥；后续SSH按正常交互认证，不保留SSH密码自动化。
