data含 contract_version,store_id,plan_id,plan_version,status,manifest,manifest_digest,approval_ref。首次发布只消费confirmed的受控执行投影，不信前端投影，不读取成本私有字段。重试先查既有slot，publishing/committed按原intent恢复或核对，不能要求重新确认、换intent或创建第二个活动。

用户明确发布时，01先持久创建/查找唯一slot (store_id,plan_id,plan_version,approval_ref)，服务器生成intent_id；换浏览器键也只能得到该slot。随后在事务外调用：

POST /api/ops/v1/internal/execution-grants

请求准确字段为 {store_id,plan_id,approval_ref,intent_id,manifest_digest,actor_ref,auth_version,capability_revision,preview_ref}；不要自行添加严格Schema不接收的别名字段。actor及身份/能力版本来自01可信发布会话。

响应data在上述绑定之外含 contract_version,grant_ref,plan_version,manifest,issued_at,expires_at；grant有效60秒。02重新校验当前不可变方案、审批、数据修订、预检及资源；sandbox_confirmed/contract_stub不得签真实grant。一个审批只有一个intent/grant/activity；同完整请求返回原grant，过期不续签、终态不重开、不同intent或身份绑定拒绝。

01拿grant后在本地短事务内重验身份/能力版本、slot、时间、摘要、价格、库存及冲突，持久创建活动、额度账本和Outbox，并将slot置committed。仅在到期前进入同slot临界区并接受有效授权的事务可完成；不能靠客户端时钟或收到响应时间倒推授权有效。

01目前没有活动管理路由。为减少猜测，采用以下待实现接口设计，如因既有约束需调整，在共同契约中一次改齐两边：

  • POST /api/v1/shop/activities：发布，body {plan_id,plan_version,approval_ref,manifest_digest,preview_ref}；Manifest由01向02读取，intent由01生成。Cookie/Origin/CSRF、activity.publish、幂等键及slot唯一约束。响应已提交活动的完整执行回执；结果未决时返回稳定intent引用与可核对状态，不伪造成功。
  • GET /api/v1/shop/activities及 GET /api/v1/shop/activities/{activity_id}：按可信店铺与能力返回执行投影，不泄露成本或其他店活动。
  • POST /api/v1/shop/activities/{activity_id}/pause、POST /api/v1/shop/activities/{activity_id}/resume、POST /api/v1/shop/activities/{activity_id}/end：body {expected_revision,reason}，activity.manage及写校验/幂等键。校验当前状态和修订，返回更新活动事实/回执。ended不可恢复，同修订冲突拒绝；到期按时钟失效，不能依赖定时任务准点执行。时钟触发的active/ended投影也要持久更新并可靠回传，不能只更新02页面显示。

02接通按钮或进入01同源活动管理页，显示未决、失败、最新phase及可恢复操作，不能留下占位按钮宣布完成。新路由需定义并测试401/403/404/409/422/503、过期/版本/幂等冲突和未知结果的准确code；它们是实施任务，不是本轮已存在的错误参数。

5.3 回执、对账、撤销与到期

01向02 POST /api/ops/v1/internal/execution-receipts推送data对象：

{contract_version,event_id,store_id,intent_id,approval_ref,manifest_digest,
 status:committed|closed_no_effect,terminal_revision,
 activity_id,activity_revision,phase:scheduled|active|paused|ended}

closed_no_effect时后三个活动字段为null；表示01已持久封闭slot、迟到发布也不能生效。committed时活动字段必需。终态不可反转，terminal_revision不随phase变化；phase用独立递增activity_revision。event_id同内容重送幂等、不同内容拒绝；旧修订不覆盖新状态，同修订不同phase冲突，ended不重开。

01需新增并受专用Bearer和店铺范围保护：

  • GET /api/v1/internal/stores/{store_id}/execution-intents/{intent_id}。
  • POST /api/v1/internal/stores/{store_id}/execution-intents/{intent_id}/finalize-expired。
  • POST /api/v1/internal/stores/{store_id}/execution-intents/{intent_id}/cancel-request，body {actor_ref,auth_version,capability_revision,reason,grant_ref}，reason非空且≤1000字符。

成功终态data使用同一完整回执。未知可返回 {status:"unknown"}。取消/到期/发布必须使用同一持久slot及锁屏障；锁后再判时钟与最新状态。取消需重新核验主体/能力；已提交返回committed，不隐式暂停。未提交才能持久closed_no_effect；锁等待超时仍未知。

02已有用户入口 POST /api/ops/v1/plans/{plan_id}/cancel-approval，body {expected_version,reason}；POST /api/ops/v1/plans/{plan_id}/reconcile-execution，body {expected_version}；服务入口 POST /api/ops/v1/internal/executions/{intent_id}/reconcile，body {store_id,finalize}。用户入口要求plan.confirm/cost.read、当前身份、Origin/CSRF及撤销幂等。

无grant可在02与grant同店锁内直接cancelled；有grant先cancel_pending，事务外请求01同slot屏障。404、超时、缺配置、坏契约、data为null/数组/标量、本地过期或查不到slot，均只能result_unknown并保留冻结，不能500或推断无效果。任何获过grant的plan禁止原地改版；另建方案前复核旧预占/核销和新增预算。
