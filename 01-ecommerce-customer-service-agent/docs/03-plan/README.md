## 2. 分批交付与进入条件

| 批次 | 任务 | 可审查交付 | 不能宣称 |
| --- | --- | --- | --- |
| B0 环境与可信基础 | T-CS-001～003 | 隔离工具链/版本记录、迁移与合成来源基础、可信身份/脱敏和测试入口 | 服务/数据库/模型已经兼容，或只是依赖声明就验收完成 |
| B1 模拟交易与商城 | T-CS-004～008 | 0元/充值/支付、多SKU/库存、商城页面、发货/本人收货与一次改址 | B1就是V1；普通取消/售后及Agent尚未齐全 |
| B2 查询与客服运行时 | T-CS-009～013 | 安全查询、消息/任务/检查点、四类适配、多轮、知识/FAQ链路 | 替身返回成功就是RAG/SQL真实模型通过 |
| B3 业务动作与人工协同 | T-CS-014～018 | Agent取消审核、工单/人工/WS、部分售后及运输异常受控退款 | Agent有售后审批权，或仅审核/填单号就到账 |

| B5 真实评测与集成验收 | T-CS-021～024 | 真实模型/数据库/浏览器、恢复/负载与91项证据、V1验收候选 | 缺少P1可豁免，或集成验收等于已部署交付 |

## 3. 执行门槛

用户已批准计划，B0之后的“继续完成”按依赖推进B1；按任务前置核对环境和隔离目标后执行。新依赖仅本项目隔离环境，不能影响父/兄弟/旧项目。B1交接后仍按批次评审边界推进；未要求创建会话、子代理或工作树。

模型地址/凭据、机器和费用范围在T-CS-021前收口；不阻塞本轮计划或前面的无外部模型开发。真实CSV接入、02/03共同签收、部署交付分别有门槛，不用未就绪外部条件掩盖本项目可完成工作，也不将其未通过标成通过。
