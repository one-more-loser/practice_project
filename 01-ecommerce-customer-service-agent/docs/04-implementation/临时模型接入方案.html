6GB 显卡：可作为起点，需实测

本机已核实为 RTX 3060 Laptop GPU，显存6144 MiB。两个0.6B模型的FP16权重估算合计约2.4GB，运行还要激活、CUDA上下文和临时张量。

建议一个隔离的本机推理进程，GPU队列并发1；Embedding微批4、重排微批1，编码长度先1024 tokens，最多20条候选重排取前5。以上是待测初值。

验证峰值显存、中文检索质量、排队和P95后再定参数；不能把模型能加载当作完整负载通过。

接入前需要补齐的六件事

  1. 重建向量：现有基线是BGE-M3。即使同为1024维，也不能混用；Qwen查询/文档编码用途要区分，发布和缓存按版本切换。
  2. 适配DeepSeek：先显式关闭思考模式验证主链；按任务处理JSON、工具调用和流式。官方兼容不等于当前适配器已经通过。官方说明
  3. 守住SQL边界：DeepSeek不拿数据库凭据；结构、白名单、权限、只读及成本限制继续执行。计划成本阈值需先在隔离数据上校准。
  4. 限制资源与费用：本机GPU共享队列；远端客服/SQL额度合并计算，记录token、重试、错误和降级。完整评测需明确费用上限。
  5. 分开验证：接口兼容 → 真实质量 → 业务回归 → 完整负载/持续运行。旧业务测试不能当作新模型质量证明。
  6. 03受控替换：只切sql能力，同一留出集重测后启用；不静默回退掩盖新模型失败。02负责运营接口联调，无需等02才能验证01。
