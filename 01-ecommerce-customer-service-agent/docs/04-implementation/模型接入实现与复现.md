## 2. 已实现的调用链

```text
电脑网页 → FastAPI身份/会话 → PostgreSQL持久任务 → LangGraph
  ├─ 公开商品/政策 → 主体消歧 → 中文关键词＋pgvector → RRF → Qwen重排 → 引用
  ├─ 本人订单/余额/物流 → 受控业务读取工具
  ├─ 复杂只读问题 → SQL API候选 → AST/资源/字段/参数/本人范围/成本门槛 → 只读角色
  └─ 写操作提案 → 顾客确认 → 业务服务重新验权/状态/幂等 → 权威流水与事件
```

- `config.py`增加受限密钥别名：优先`CS_CHAT_API_KEY`、`CS_SQL_API_KEY`，否则引用既有`DEEPSEEK_API_KEY`。密钥未复制进JSON、网页、模型上下文或报告。
- `ModelGateway`显式关闭DeepSeek思考模式，区分Qwen的query/document用途。SQL适配器给模型省略的传输元信息绑定本次请求的已知契约；已返回但冲突的Schema仍拒绝。不补造SQL、参数、身份或业务结论。
- `AgentGraph`把后端工具结果作为数据消息提供给模型，不冒充模型自己的回答或系统指令。游客本人查询提示登录，公开规则查询不要求登录。最终业务事实继续由受控工具结果渲染；未知格式不执行动作。
- 取消审核改用实际Pydantic JSON Schema，明确`checks`为数组，并绑定事实摘要与允许的规则/事实引用；服务端仍校验状态、金额、版本和退款唯一性。售后审批权没有转给模型。
- 测试默认指向不存在的模型配置文件，普通pytest不触发付费调用。真实验证须显式使用项目内配置；浏览器真实模型套件还要求`CS_REAL_MODELS=1`和固定test目标。

Qwen服务代码位于`model_service/qwen_service.py`，仅监听`127.0.0.1:8010`，不加载远端自定义代码，不向该进程传递API密钥。GPU并发1，有界等待队列8；Embedding微批4、重排微批1；超1024 tokens拒绝并报错，不静默截断。取消HTTP等待不提前释放尚在执行的GPU任务。

## 5. 失败历史与未完成门槛

- 首次SQL返回省略传输元数据，契约检查拒绝；现绑定请求常量，冲突仍拒绝。首次取消返回`checks`字典，严格审核拒绝且未退款；现传真实JSON Schema后真实链路通过。失败报告仍留`.runtime/*initial.json`。
- 游客私有查询曾要求订单编号，现改为登录引导；工具结果曾以assistant角色送入模型，现作为数据消息。早前浏览器仍出现`agent_protocol_error`或无引用引导，独立5题诊断和最终5题浏览器通过；**原因尚未覆盖全部波动，重复性/负例/留出集仍待验证**。非法响应保持关闭，未放宽审批校验或伪造完成。
- 临时结构诊断包装器一度漏`return`，导致诊断运行自身的TypeError；已移除包装器，不把它算作模型失败。结构日志无文本/参数/密钥，保留在私有`.runtime`供追溯。
- 仍需70+30完整RAG、SQL80/40、真实多轮/FAQ/Skill留出集、模型替换回归。已有70题不是独立留出；当前重排阈值不等于可靠性证明。
- 当前确定性事实渲染还会拼接其他召回政策，回答较长；命中与引用可打开不代表答案简洁相关。该问题已登记LIMIT-V1-11，后续按依据选择与多意图质量评测收口。
- 仍需500订单/50SKU/200真实片段、10并发15分钟、连续8小时；真实生成失败、超时和降级单列。应用SQL计划成本限额未校准，保持fail closed，本轮测试预算1000不复制到应用。
- `chat_stream`验证了供应商SSE完整组装；网页仍按持久事件交付完成结果，**逐token首段未实现**。每能力/进程限流也不等于供应商全局额度控制。
- 现有知识切分按字符，服务按1024 tokens拒绝；更长中文片段需验证并完善切分，不能承诺模型卡长上下文在6GB上可用。若后端移至VM，loopback模型地址须重新设计网络与鉴权。
- 前一主版本浏览器、02聚合真实消费、03最终SQL服务共同签核仍待补。未训练、未接真实资金、未部署前后端到服务器或公网。
