## 2. 当前调用链与实现

1. 顾客或游客建立服务端会话，消息与run、task、接收事件同事务提交，202才表示持久接收。同client_message_id重放查原结果，异参拒绝。
2. 启动生命周期运行持久Worker。短事务领取租约，LangGraph使用原生PostgreSQL检查点；模型请求期间不持业务锁。恢复时检查租约栅栏、模式epoch、有效登录/角色、数据批次和图版本。
3. 已审核FAQ可以直接复用。其他问题由模型产生受控只读工具请求；商品/订单/物流/余额走业务读取，复杂SQL只接受候选并经过独立防线。没有模型配置时给出失败状态，不返回演示答案。
4. 余额、价格、库存、订单、物流及检索摘录使用服务端事实生成回复，模型不能覆盖金额或状态。无事实的模型承诺替换为咨询引导；澄清保存受控槽位，三轮终止，不冒称已转人工。
5. 提交回复前再次核对身份、栅栏与引用有效性。回复、最终状态和公共事件同事务提交；完成检查点后尚未提交回复的任务可恢复，不重复调用模型。
6. 前端用SSE读取持久事件，再读取受控历史。关闭窗口仅断连，重新打开恢复；停止回答是独立取消。未知接收结果沿用原消息编号与原内容重试；换账号或角色清空界面并重新鉴权，不合并游客与登录会话。

模型调用只存在后端。Graph禁用环境中意外开启的外部追踪；消息、工具结果及检查点沿用隐私门面。没有新增退款审批、资金写入或模型决定主体身份的入口。

## 3. 知识与FAQ

- 新增0014与0015迁移，知识单元/版本/片段/FAQ具备来源、时间、可见范围、商品适用范围、审核发布记录和索引版本。审核、发布、停用记录审计；不是存在Embedding就直接发布。
- 知识管理员可输入文本、创建版本、查看内容、审核、索引发布和停用；没有新增文件批量导入/OCR平台。知识升级退休旧版本，并停用绑定旧版本的FAQ。回退通过复制旧内容建立新版本，重新审核和发布，保留历史。
- FAQ可以绑定知识版本，或引用contracts/knowledge_sources.json中的已批准规则基线；未知来源不能发布。规则基线变更须同步停用该来源，不能只修改文档而继续复用旧FAQ。没有独立Redis缓存，读取时复核来源/可见性/有效期。
- 文档和查询使用jieba搜索分词与受控商品/政策词典；关键词和精确向量各召回20，RRF合并取10，Qwen重排后最多5个引用。重排外发前和结果返回前重新过滤；无服务时标记降级，不能把关键词回退算成向量/重排成功。
- Embedding记录模型、服务修订、1024维及索引版本。测试向量只允许显式测试服务写入固定测试库的test_only索引，在线检索不读取该索引；API不提供测试开关。
- 商品名称、别名、SKU由受控目录识别。多商品不猜测，未识别到商品时只查询通用资料，不能拿另一商品资料填补缺失。

数据：[14条FAQ草稿](../../data/synthetic/faq-sim-v0.2.json)、[FAQ治理负例](../../tests/evaluation/faq/faq_governance_negatives.json)、[30条流程脚本](../../tests/evaluation/conversation/scripted-cases.json)、[70可答/30负例RAG候选](../../tests/evaluation/rag/dataset.json)。FAQ沿用原编号；RAG与FAQ分集。RAG候选未执行真实BGE/Qwen评测，200片段容量批次留待质量/负载验收。应用库只导入FAQ草稿，不伪造审核人或发布时间。

## 4. 数据库与运行配置

数据库保留在Debian独立cs01-db项目，不改旧ecommerce-deploy。本机后端和前端只用于临时验证，未部署到Debian。连接信息在受限.runtime中，不复制到报告。

当前Schema及验证结果以[B2证据](../06-acceptance/B2/README.md)为准；0010之前部署证据不是当前版本证明。应用库升级先做新的逻辑备份与28张原业务表摘要，迁移和检查点setup后核对原数据；禁止清空应用库或down -v。

每API进程连接预算：业务池最多15、只读SQL池最多4、检查点1，共20；两进程上限40，数据库max_connections=60。模型并发按单进程共享网关限制，多个进程仍需核定上游总预算。SSE当前轮询0.5秒，10条活跃连接约20次补偿读取/秒；这是容量估算，不是实测吞吐或15分钟负载结论。

模型配置路径.runtime/model-services.json仍不存在。客服、SQL、Embedding、重排分开配置，示例不是可用服务。SQL型号由03决定，01不固定型号；未核定计划成本时，候选执行保持拒绝，固定业务查询可以使用。真实服务、时间/参数契约、成本初值与业务回归需在T-CS-021核验。

## 5. 复现

所有命令在项目根目录执行，使用项目Python和指定Node。不要用固定本机profile的scripts/check.ps1跑Debian回归。

```powershell
& backend/.venv/Scripts/python.exe scripts/check_b2.py --profile debian
```

该入口只清理经隔离守卫核对的固定测试/升级库，不清理应用库。原始JUnit保留在受限.runtime/b2-backend.xml。

浏览器前先等后端回归退出，再准备测试库；不能与pytest并行清理同一数据库：

```powershell
& backend/.venv/Scripts/python.exe scripts/prepare_b2_verification.py --profile debian
$env:CS_VERIFICATION_TARGET='test'
$env:CS_EVIDENCE_SCOPE='B2'
$env:CS_BROWSER_CHANNEL='chrome'
$env:PLAYWRIGHT_BROWSERS_PATH=(Join-Path (Get-Location) '.runtime/ms-playwright')
```

在frontend目录用Node24.19.0执行npm-cli.js的run build、run test和run test:e2e；系统Node22.13不符合当前Vite要求。具体绝对工具路径见HANDOFF.MD。Playwright会启动回环服务并结束进程，不执行服务器部署。浏览器旅程通过后，在根目录执行：

```powershell
& backend/.venv/Scripts/python.exe scripts/verify_b2_http.py
```

该脚本只使用8002空闲端口和固定测试库，模拟已ACK但Worker未开始时进程终止，重启后通过真实FAQ恢复；没有注入模型替身。只终止自己创建的进程。
