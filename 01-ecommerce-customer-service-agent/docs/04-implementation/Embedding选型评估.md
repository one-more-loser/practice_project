# Embedding选型评估

2026-10-23。用户要求先评估BGE-M3与Qwen，再确认采用Qwen。以下区分公开资料、项目事实和运行验证；没有宣称完成两模型本机A/B。

## 选择

采用 **Qwen/Qwen3-Embedding-0.6B，1024维**，重排采用Qwen3-Reranker-0.6B。BGE-M3保留为对照/回退候选，不同时维护两套在线索引。主客服和临时SQL只允许用户指定的 **deepseek-flash**。

## 比较依据

| 维度 | BGE-M3 | Qwen3-Embedding-0.6B | 对本项目的含义 |
| --- | --- | --- | --- |
| 公开多语言MTEB任务均分 | 59.56 | 64.33 | Qwen技术报告的同表结果，供应方汇总含历史榜单数据，不是本机独立复测 |
| 同表检索子项 | 54.60 | 64.64 | 支持优先验证Qwen稠密召回；不能解释为客服正确率提高10.04个百分点 |
| 中文检索 | 支持中文与多语言 | 官方C-MTEB Retrieval为71.03 | 当前来源缺少两者同口径中文直接对照，不补造BGE成绩，不宣称已证明中文全面领先 |
| 输出/长度 | 1024维，最多8192 tokens | 最高1024维，最多32K tokens | 已切分的政策与商品资料无需依赖32K；两者能适配现有Vector(1024) |
| 功能 | 稠密、学习式稀疏、ColBERT多向量 | 当前方案使用稠密表示 | 既有系统是数据库关键词＋稠密RRF，不等于启用了BGE三路检索；BGE扩展能力不是当前实际收益 |
| 编码与接入 | XLM-R编码器，CLS池化；无需查询指令 | 查询指令、末token池化，固定归一化 | BGE接入较简单；Qwen需显式query/document用途，已经纳入适配 |
| 本机资源 | 需在相同精度/长度/批量下测 | 需测Embedding与重排共同常驻 | 同为约0.6B级别，不能仅按参数量推断速度或6GB下并发容量 |

公开数字来源：[Qwen技术报告v3，Table 2/8](https://arxiv.org/html/2506.05176v3)。规格和编码来源：[BGE官方模型卡](https://huggingface.co/BAAI/bge-m3)、[Qwen官方模型卡](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B)。报告/模型卡的基线收集时间说明不完全一致，因此只引用对应表格的历史结果，不称“当前排行榜第一”。也不把Qwen8B的成绩套到0.6B。

选择Qwen的理由是公开稠密检索证据与当前链路相符，且两者没有已证实的资源差距足以推翻该选择；“重排同为Qwen”不是检索效果必然更好的理由。最终质量/性能仍由项目评测决定。

## 验证要求

1. 先验证权重完整性、CUDA可用和双模型实际加载，记录显存峰值、编码长度、批量与依赖版本。
2. 跑当前70条可回答/30条反例集合；真实稠密召回、数据库关键词、混合召回及重排分层记录。不能把7个规则来源上的高命中率当成200片段规模验收，也不能把动态订单问题的近邻向量当业务答案。
3. 固定中文同义问法、商品别名、否定/时态、政策版本和无依据问题；真实模型与真实接口通过后再跑负载。当前集属于已有合成回归，不能冒充未见留出集。
4. 若Qwen未达到已批准质量/资源门槛，再在相同语料、分段、精度和设备下运行BGE对照，独立建索引。禁止跨模型混算相似度或直接比较两模型的原始分数阈值。
