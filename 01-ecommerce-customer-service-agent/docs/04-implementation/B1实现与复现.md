# B1 模拟交易与商城实现

2026-10-22，依据已批准REQ-CS-v0.2、DESIGN-CS-v0.1、PLAN-CS-v0.1。用户在B0交接后要求“继续完成”，本轮按依赖推进T-CS-004～008；没有扩大到B2模型和客服运行时。界面采用用户指定的暖白＋橙色，以及[Apple HIG社区Skill](Apple设计Skill采用记录.md)。本文件记录本批实现，运行结论以[B1验收记录](../06-acceptance/B1/README.md)为准，提交用户评审。

## 1. 实际入口和调用链

浏览器Vue路由 → 同源`/api/v1` → FastAPI会话/当前角色/CSRF → 业务服务 → PostgreSQL事务 → operation/业务记录/流水/审计/Outbox一并提交 → 成功响应。后端数据库身份、金额、库存、订单版本及改址次数为权威来源；Pinia仅保留会话视图。

| 入口/文件 | 实际职责 |
| --- | --- |
| [业务API](../../backend/src/cs_agent/business_api.py) | 公开商品、本人余额/购物袋/报价/订单、确认、店铺商品库存和发货/模拟物流；输入拒绝未知字段 |
| [操作仓储](../../backend/src/cs_agent/actions/repository.py)、[确认服务](../../backend/src/cs_agent/actions/service.py) | 同主体/角色/店铺/批次/动作/请求编号去重；确认绑定参数摘要、资源、版本、授权版本及5分钟有效期 |
| [钱包](../../backend/src/cs_agent/wallet/service.py) | 零元开户、模拟充值、余额读取、连续流水、支付内部扣账；无管理员余额编辑入口 |
| [商品](../../backend/src/cs_agent/catalog/service.py)、[库存](../../backend/src/cs_agent/inventory/service.py) | 当前商品/规格/价格/可售数、店铺维护、版本冲突、库存增量与变动记录 |
| [交易](../../backend/src/cs_agent/commerce/checkout.py) | 购物袋、本人收货表单、报价、创建订单及库存预留、支付扣款和消耗预留 |
| [查询](../../backend/src/cs_agent/commerce/query.py) | 本人/本店范围、订单/明细/金额/政策/物流、服务端可操作状态；店铺只收到脱敏联系信息 |
| [履约](../../backend/src/cs_agent/commerce/fulfillment.py) | 整单发货、承运签收记录、一次改址、本人整单收货 |
| [超时任务](../../backend/src/cs_agent/commerce/expiration.py)、[进程入口](../../backend/src/cs_agent/main.py) | 每5秒扫描最多100个到期未付款订单，使用数据库锁释放预留；重启后从持久业务记录继续 |
| [前端路由](../../frontend/src/app/router.ts)、[API客户端](../../frontend/src/lib/api.ts) | 商城、登录、购物袋、结算、余额、订单和店铺页；失败反馈、超时和原编号重试 |

实际页面位于`frontend/src/pages/`，共享表单和确认框位于`frontend/src/components/`。与计划中的`features/`目录命名不同，职责与任务编号保持一致；本批业务路由集中于一个API模块，领域服务分开。后续扩展可按领域拆路由，不在此增加第二套接口。

## 2. 关键业务与失败行为

- 开户余额0；充值12.34元＋0.66元形成两笔入账后为13元。API金额为CNY分单位字符串，数据库为有界整数，浏览器用BigInt处理金额；拒绝零、负数、指数、非法精度和溢出。
- 报价5分钟有效，包含SKU/数量/价格版本、商品版本、购物袋绑定、收货输入引用和政策版本。创建订单再次检查现价、上下架、库存及购物袋版本；变化时要求重新报价，不能按旧页面静默成交。
- 创建订单固定商品/金额分摊/政策和收货快照，预留库存15分钟。应付分摊`allocated_minor`与实际已付`paid_goods_minor`分开；未付款明细实付为0。尾差规则`ALLOC-LAST-UNIT-v1`把余数放在本明细最后一件，紧凑保存基准额/尾件额/数量。
- 付款按锁定订单应付扣本人余额；余额、支付记录、唯一流水、库存预留消耗和订单付款状态原子提交。100元付40元余60元；30元付40元拒绝，订单未付款、预留仍在原有效期内。发货不再扣一次库存。
- 未付款取消无需资金动作；15分钟到期任务释放预留一次。已付款未发货的普通取消入口保留，当前返回“须经资格审核，该能力尚未开放”，由T-CS-014完成真实Agent审核；没有用规则替身冒充审核通过。
- 改址必须由本人使用新填写的`address_change`输入确认，且有效未发货订单的`change_count=0`。成功创建第二份不可变快照、改址记录并置1；刷新、换会话或重复确认不恢复机会。发货和改址锁同一订单，先成功者决定另一操作是否仍有效。
- 发货仅店铺管理员，数量映射必须覆盖全部订单明细及原数量。成功后进入运输中。模拟承运签收只更新包裹轨迹，不生成本人收货记录；正式收货须顾客本人确认。售后和运输异常工单属于后续批次，页面没有伪装为已开放。

## 3. 去重、锁及恢复

同键同参返回持久原结果，同键异参409；同一确认换键也核对原结果。跨24小时不删除业务唯一性。业务拒绝回滚业务保存点，但在外层事务保存拒绝结果；事务整体提交失败则不会返回业务成功。数据库未知结果或连接断开不能据此生成新资金动作。

浏览器为待核对写请求保存原操作编号与请求摘要，按主体/角色/授权版本隔离；不保存表单原文、Cookie、CSRF或模型密钥。登录、角色切换不会把其他主体的待核对编号当成本人操作。充值未知结果时，原金额重试复用编号；更换金额前提示先核对上一笔。确认框忙碌时禁用重复提交，网络未知保留原确认，明确业务拒绝后允许关闭并重新核对。

锁顺序按路径约束：确认/operation入口 → 报价/购物袋 → 订单（若已有）→ 商品ID（仅建单核对商品状态）→ SKU/库存按ID排序 → 钱包 → 持久结果。库存批量超时任务先锁到期订单，再对整批SKU排序获得库存锁；其他库存路径不反向等待商品。事务中不等待模型或外部网络。运行角色DB语句超时2秒，故障由客户端原编号核对及后续扫描恢复；这不是完整多进程/故障和负载验收。

订单当前地址有同订单复合外键，事务提交时复核，不能指向不存在或其他订单的快照。确认关联、支付/发货/收货/改址唯一性及金额/库存检查约束由数据库继续约束。当前所有Outbox仅在本项目持久化，未实现02事件投递或宣称对方消费成功。

## 4. 数据、权限与合理默认

迁移从B0的0003增量到`0010_business_integrity`。0004操作/钱包、0005商品库存、0006交易、0007履约、0008分摊与实付、0009个人表单新增权限、0010快照关联/确认外键/查询索引。历史迁移不导入当前表定义执行；禁止自动破坏性回退。

[实际字段字典](B1实际数据字典.md)列出B1已建表的字段、类型、空值及关联；[来源映射](../../tests/fixtures/business_source_map.json)对照流程和合成字段。订单、明细、包裹保持独立粒度。后续退款/工单/消息/模型实体随所属任务增量补齐，当前不存在的域不宣称已物理实现。

合成目录为[SIM-CS-CATALOG-v1](../../data/synthetic/catalog-v1.json)：4商品、5SKU，包含缺货和最后一件；初始库存来自该批次，后续变更形成流水。原B0身份批次和来源指纹不改写。重复seed保留已发生的余额/价格/库存/交易，不重置账户。成本、供应商和外部CSV编号未知，保留NULL；没有冒充真实数据已有这些值。

实现默认：当前模拟包邮、无促销，仍保留商品/优惠/运费、政策版本和退款分项；未新增促销引擎。一次结算最多50种SKU属于资源保护，数量使用合法整数，不增加商品业务限购。当前新建商品入口创建首个规格和零库存，现有多规格均可维护售价/规格/上下架及库存；不扩展为商品管理平台。

公开DTO无成本/供应商；顾客仅本人；店铺管理员仅本店履约和商品维护，联系电话末四位、地址至市，无完整信息入口。客服/主管/知识角色不能借本批端点充值、支付、发货或获取本人完整资料。完整收货信息仅本人订单详情和本人资料专用路径返回，通用列表/确认/审计/Outbox保持脱敏或引用。

## 5. UI采用与验证边界

“橙日生活”为可调整店铺展示名。暖白底、橙色操作、商品插画、对齐和留白；分类/SKU/缺货/忙碌/成功/拒绝都使用文本，资金操作显示金额与确认，改址明确只有一次。表单有标签，支持键盘焦点和跳转主内容，尊重减少动画偏好。商品图为本项目SVG示意插画，不声称实拍或借用Apple资产；没有伪造促销价、评价或客服在线状态。

Skill固定提交、MIT许可和项目内安装见[采用记录](Apple设计Skill采用记录.md)，无需MCP运行服务。平台专用规则按电脑网页解释，未扩展手机、App或原生桌面客户端。

实际浏览器使用Playwright自带Chromium，1440×1000与1280×800；截图只保存公开商城/店铺脱敏工作台，关闭包含登录和个人资料的trace/video。没有用jsdom代替浏览器，也没有把此结果当作Chrome/Edge各当前/前一版本或完整无障碍认证。
