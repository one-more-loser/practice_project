## 1. 目标、依据与需求状态

面向一家模拟电商店铺，顾客在商城嵌入式客服中咨询商品和政策，查询本人订单、物流与售后，通过多轮澄清确定诉求，必要时建立工单并由人工接管。系统应使每项事实有来源、每项访问有权限、每项写入有明确意图和结果，并向运营项目提供脱敏反馈、向 SQL 微调项目提供查询能力契约。

## 4. 端到端流程与用户故事

### 4.1 公开咨询与本人查询

1. 顾客从商品/订单页面打开客服；页面上下文以“候选线索”传入，不授予数据权限。
2. 识别本轮一个或多个意图，列出需澄清的商品/SKU/订单/时间条件；不跨账号继承指代。
3. 商品说明与政策走获准知识；价格、库存、订单、物流、售后走获准业务事实。混合问题分别查询、分别标来源和时间。
4. 未登录而涉及个人事实时暂停该子任务，引导登录；公开子任务可完成。登录后建立本人会话，再由顾客重新确认原诉求。
5. 查询成功输出结论、证据或记录卡片；无记录、越权、条件不足、冲突、源过期、工具失败分别处理，不把失败说成“没有订单”。
6. 用户修改条件时更新本任务条件并重查；多订单指代不清时列本人候选，待选择后继续。

### 4.2 工单与人工闭环

1. 顾客提出投诉/建单/转人工，或机器人发现知识冲突、查询持续失败、规则无法处理；系统给出原因与可选下一步。
2. 建单前展示类别、摘要、关联订单、必要联系信息与提交后效果；顾客确认后调用业务接口，返回工单号。
3. 工单进入本店团队队列；规则给出分类、优先级、分派建议，主管可修正并留理由。
4. 转人工排队时冻结机器人主动回答与新动作；人工接单后显示操作者及接管状态。
5. 人工处理、更新工单并给顾客可见结论；内部备注与机器人检索隔离。暂时无人时保留排队/工单状态，不显示“已接通”。
6. 客服点击“结束服务”后，人工接管结束且当前会话自动切回客服 Agent，无需顾客点击恢复；顾客端名称使用“店铺客服”。恢复只读取获准且脱敏的上下文，旧待确认动作重新检查权限、有效期和当前状态，不自动重放写操作。关闭工单或结束人工服务不等于关闭顾客会话。

### 4.3 最小模拟购买与跨项目协同

顾客可单SKU立即购买，或按Q22使用购物车选择多个SKU，确认明细、最终金额和本人地址后建立待支付订单，再确认余额支付。支付以成功扣款及关联支付记录为准；余额不足不标已支付，重复提交不重复扣款。店铺管理员整单发货后进入运输中；模拟承运签收与顾客本人整单确认收货分别记录，正式售后等本人确认。无真实资金、短信或快递调用；缺货、变价、重复提交和状态冲突须可演示。

发货前，顾客可对每个订单成功修改一次收货信息；计次细化建议为修改失败或取消确认不消耗成功次数。成功后改址按钮置灰并显示“地址已修改”，订单保存改址记录，普通取消入口仍保留并按订单状态判断是否可执行。店铺点击“发货”并成功变更业务状态后，该订单禁止改址，服务端必须按发货事实与改址次数复核。修改与发货同时发生时，不得出现发货后仍改址成功的结果。修改前后完整收货快照仅保存在受控业务数据中；审计日志引用快照标识及脱敏差异，不写完整电话地址。改址计数、确认/发生时间及发货事实需可追溯，客服/主管展示遵守 C-18。

获准退款使用对应顾客的店铺余额账户；申请、审核、执行、余额入账是不同事实。同一退款仅一次入账；失败或结果不明不先显示到账。按Q26，开户余额0元，顾客输入金额并点击模拟充值后等额增加本人余额，保存充值记录及唯一流水；余额用于后续购物，退款也退回本人余额。不接真实支付，不支持提现/转账。充值只保留输入校验、顾客提交、入账结果与重复请求核对，无充值审批或支付渠道接入。

当前按C-30～C-34：已付未发货取消由Agent审核留痕，执行前复核；发货后运输中，异常退款走独立工单；本人确认收货后才开放正式售后，核验收退后退款。取消与发货保持业务先后，退款不能重复、超额或入他人账户；“已审核”与“已到账”分开记录。

隐私输入的细化建议：完整收货信息由顾客本人通过受控地址表单维护，客服及模型只接收已选地址标识/脱敏摘要；聊天中出现完整电话或详细地址时，在进入模型和通用日志前脱敏。完整收货快照属于获准业务数据，不作为通用日志或模型上下文。顾客本人查看完整信息的接口应独立鉴权，不能被客服角色或模型工具复用为绕过脱敏的入口。

客服按业务日汇总热点/缺口/投诉与工单统计，经脱敏校验输出给运营消费方；接收是否成功与业务统计是否完整分别记录。SQL 查询先使用基线模型，03 项目交付符合契约的版本后再做兼容和业务回归；替身验证不代表真实模型或兄弟项目联调通过。

## 5. 功能需求

统一约定：除注明P1/候选外均为建议P0；V1需完成最终基线内全部P0/P1。当前状态见C-01～C-48及最新答复覆盖说明。每条采用“角色/触发—前置与输入—正常—异常/拒绝—输出/状态—权限—验收”七项。BR为第6节业务规则，AC见矩阵，未决分支仍待定稿。服务错误应有用户可理解说明、关联标识和下一步，不输出SQL、堆栈或内部敏感详情。

### FR-CS-001 最小商城与客服入口

- **角色/触发：** 游客或顾客打开商品列表、商品详情、我的订单页并启动客服。
- **前置与输入：** 当前店铺、商品/SKU 候选；订单页需登录；输入包括咨询文字与当前页标识。
- **正常：** 列表选择商品和 SKU，详情展示规格与公开事实；客服保留页面上下文并允许用户纠正。
- **异常/拒绝：** 商品下架显示不可购；伪造页面订单号仍需鉴权；页面数据加载失败不得用旧价格冒充现价。
- **输出/状态：** 公开商品卡、订单入口、客服窗和“模拟店铺”标识；页面跳转不丢已提交消息。
- **权限/规则：** 公开信息可游客读；个人页面遵守 BR-CS-001～003、008。
- **验收：** AC-CS-001、013、052。

### FR-CS-002 登录身份与资源归属

- **角色/触发：** 顾客登录、退出、账号停用、身份到期或发起个人查询。
- **前置与输入：** 预置模拟账号；可信登录凭据由身份能力校验，聊天文本/页面 user_id 不作为身份。
- **正常：** 获取本店主体与角色；每次读写、历史读取、断线恢复都检查资源归属；退出后个人数据入口失效。
- **异常/拒绝：** 未登录提示登录；他人/不存在资源统一提示“未找到可访问记录”；切换账号不带入上一账号上下文。
- **输出/状态：** 当前身份、授权范围、登录失效事件；失效期间不得继续输出个人流式内容。
- **权限/规则：** BR-CS-001～005、016；不以订单号和手机号组合充当认证。
- **验收：** AC-CS-002、015、021、058。

### FR-CS-003 单 SKU 模拟交易

- **角色/触发：** 登录顾客选择立即购买、提交订单、确认使用余额支付；获准店铺人员推进模拟履约。
- **前置与输入：** 上架SKU、正整数数量、本人模拟地址、当前报价和确认；默认选中数量1，可提交数量受有效可售库存约束，不为演示样本另设1～5件业务上限；金额由业务来源重算。
- **正常：** 展示最终金额和库存检查结果；确认建待支付订单；顾客确认余额支付后成功扣款并标已支付；店铺管理员整单发货后运输中、顾客本人整单确认收货，模拟承运签收单独记录。
- **异常/拒绝：** 缺货、价格变化先重展示确认；余额不足/账户不可用/支付失败不算成交；重复点击返回同一结果且不得重复扣款；非法状态推进被拒绝。
- **输出/状态：** 订单及金额快照、余额扣款流水、支付结果、库存变化和脱敏审计；超时未支付 15 分钟关闭并释放占用的数值为建议，时钟可在演示中推进。
- **权限/规则：** BR-CS-010～014、018～019、025；支付仅测试，不收集银行卡，不产生真实扣款。
- **验收：** AC-CS-003～004、032～033、059。

### FR-CS-004 会话归属、历史与任务生命周期

- **角色/触发：** 顾客新建/继续/关闭会话，打开历史；人工接入关联会话。
- **前置与输入：** 会话 ID、消息 ID、可信主体；游客使用隔离的匿名会话范围。
- **正常：** 展示本人历史与任务状态；每轮关联一组子任务；关闭会话保留获准历史；未终结工单独立保留。
- **异常/拒绝：** 不可读他人会话；登录、退出或换号建立新的身份范围，匿名内容不自动并入本人历史；已关闭会话只读，新诉求新开会话。
- **输出/状态：** 会话 open/closed、协同状态、按顺序的持久消息、任务终态及可继续入口。
- **权限/规则：** BR-CS-002～004、016、024～025、030。
- **验收：** AC-CS-005、029～031、054。

### FR-CS-005 多轮澄清、指代与多意图

- **角色/触发：** 顾客缺订单/SKU/时间条件、使用“那单”、改口或同轮提出多个诉求。
- **前置与输入：** 当前身份范围内的历史、获准候选、意图及已收集条件；一次最多处理 3 个子意图，超出提示选择。
- **正常：** 保留已提供条件；每轮提出一个关键澄清问题；列本人候选；条件修改使受影响的旧查询结果失效；分项展示完成/待澄清/失败。
- **异常/拒绝：** 多个候选不猜测；连续 3 轮仍无法确定时提供人工/工单选项；一项失败不覆盖其他已完成项；写动作不能跟随查询隐式执行。
- **输出/状态：** 结构化条件摘要、子任务 awaiting_input/running/终态；答案区分各意图结果。
- **权限/规则：** BR-CS-016～018、020；候选不能包含他人记录。
- **验收：** AC-CS-006～007、019、050。

### FR-CS-006 消息顺序、流式反馈与恢复

- **角色/触发：** 顾客发送消息、等待查询、断线重连、重复点击发送。
- **前置与输入：** 客户端消息标识、会话序号、最近已读事件位置；同会话同一机器人任务至多一个运行。
- **正常：** 先确认接收，再展示澄清/检索/查询/待确认等状态；正文增量带消息归属；重连补历史并去重；完成仅出现一个终结结果。
- **异常/拒绝：** 忙时不静默丢弃新消息，提示等候或允许取消当前只读任务后重发；未核验业务事实不可先流出；断流显示未完成；人工接管后丢弃迟到机器人输出。
- **输出/状态：** accepted、progress、answer_delta、citation、confirmation_required、handoff_changed、completed/failed 等可观察语义；不限定传输协议。
- **权限/规则：** BR-CS-002、008、019、024～025；恢复流也重新校验身份与接管状态。
- **验收：** AC-CS-008、029、046～047、053、080。

### FR-CS-007 本工程最小知识准备、发布状态与失效

- **角色/触发：** 知识管理员维护商品说明、运费/优惠/退换货/保修条款，客服接收获准的知识版本与检索能力。
- **前置与输入：** 来源、版本、商品/店铺范围、可见性、有效期、发布状态和负责人；受控商品/政策文本与索引，不与顾客附件/订单CSV混用；多格式/批量UI不在当前基线范围内。
- **正常：** 本工程内按最小流程整理/切分/Embedding并形成可检索版本，检查适用/可见范围和引用；更新/停用/过期影响检索及缓存，不要求独立RAG项目。
- **异常/拒绝：** 缺来源/版本/有效范围或知识服务不可用时不可假称有效；冲突/未发布内容不进入顾客答案；解析失败不得发布；不能把检索接口成功当作已完成文件平台验收。
- **输出/状态：** 知识版本、处理/发布状态、检索可用性与失效确认；draft/validating/published/retired/failed 为候选语义，存放位置与接口由后续边界评审决定。
- **权限/规则：** BR-CS-005～009、029～030；停用和到期影响检索、引用访问及缓存。
- **验收：** AC-CS-009～010、057～058。

- **异常/拒绝：** 禁止完整电话地址、密钥、令牌或未获准原文进入通用日志/模型/追踪/检查点；日志查询需独立授权；日志不可用不允许用日志猜账务结果。
- **输出/状态：** 可检索的脱敏链路与失败分类；保留和删除规则按 NFR-CS-010 待评审。
- **权限/规则：** BR-CS-002～005、030、037；员工无客户信息解密入口。
- **验收：** AC-CS-039、051、053～054、064、067、076、079。

### FR-CS-026 数据字典、合成样本与证据

### FR-CS-027 确认收货后退货退款（P1）

- **输出/状态：** requested/reviewing/approved/rejected/awaiting_return/processing/refunded 等候选语义；每笔退款与余额流水关联。
- **权限/规则：** BR-CS-003～004、010、015、018～019、025、040、043～044、048、050；C-33/034/038/041已确认，Agent不自行指定退款额或审批超期。

### FR-CS-028 普通取消与Agent审核（P1）

- **角色/触发：** 顾客从订单页或客服选择取消并确认。

- **正常：** 已付未发货由顾客确认，Agent受控读取订单/付款/发货/可退额，审核资格并记录结论/依据；通过后业务接口复核最新权限/状态/金额再取消退余额。待付取消建议关闭并释放占用，不产生退款；发货后为运输中，不直接进入售后。
- **异常/拒绝：** 越权、过期确认、已取消/关闭或状态变化拒绝新动作；Agent拒绝/无法完成审核时不直接退款，建议人工协助补齐事实后重新审核，不授予人工绕过该审核的权限；审核通过但发货先成功仍拒绝普通取消；重放核对原结果。
- **输出/状态：** 审核中/通过/拒绝/需人工、审核ID、事实/规则/模型版本、依据摘要、确认及执行/退款/余额关联；审核、执行和到账分别记录。
- **权限/规则：** BR-CS-003、012～013、018～019、025、039～040；Agent审核取消资格不等于售后审批或写SQL权限。
- **验收：** AC-CS-042、065、068、081、091。

### FR-CS-029 每单一次改址（P1）

- **角色/触发：** 顾客对本人尚未发货订单选择修改地址并确认。
- **前置与输入：** 服务端确认订单仍处于待付/已付未发货的有效状态、尚未成功发货、成功改址次数为0、本人选中的有效收货信息；完整地址只在受控本人表单处理。已取消/关闭订单不能因“未发货”获得改址权，此为终态细化建议。
- **正常：** 更新订单收货快照并保存一次成功改址记录；按钮置灰、显示“地址已修改”；刷新/换会话读取同一业务记录。
- **异常/拒绝：** 发货后、已取消/关闭或第二次成功改址拒绝；顾客放弃确认或已核实未写入的失败不消耗次数为默认建议。超时/结果不明先查业务结果，不能恢复次数或另发新改址；并发发货先成功则改址拒绝，改址先成功则发货用新地址。
- **输出/状态：** 成功次数、快照关联、发生/确认时间、脱敏审计；保留普通取消及查询，正式售后按确认收货门槛开放；未收到货退款走运输异常工单，不能因改址绕过门槛。
- **权限/规则：** BR-CS-003、018～019、025、037；前端灰显不能代替服务端校验。
- **验收：** AC-CS-043、062～065、067、091。

### FR-CS-030 购物车与多SKU结算（P1，Q22确认纳入V1）

### FR-CS-031 最小知识准备与FAQ（FAQ为P1，Q27确认纳入V1）

FAQ是常见问题与标准答案；用户在释义后确认纳入V1，并要求本项目编制模拟数据。本轮先在7.4提供可评审样本，不创建数据库种子、执行发布或认定功能已实现。答案复用的具体存储/匹配方案在后续设计评审决定，不因此要求新增缓存服务器。

- **角色/触发：** 知识管理员维护并单级审核FAQ（Q29确认），主客服处理稳定问答；需求编写方编制合成样本，主管审核例外案例/Skill。
- **前置与输入：** FAQ问题/同义表达、标准答案、主题/商品/政策适用范围、来源及版本、可见范围、有效期与审核状态；未发生发布/审核不伪造操作者及时间。
- **正常：** 维护候选→核对来源→审核发布→命中且适用时复用标准答案并保留来源；变更/停用使旧答案失效。最小知识文本准备/Embedding/索引仍在本工程，不依赖旧RAG改造。
- **异常/拒绝：** 未审/过期/停用/范围不符/冲突不复用；不确定或多条冲突时澄清或转RAG，个人动态事实走受控查询，不因问法相似返回历史顾客结果；不默认引入完整多格式导入平台。
- **输出/状态：** draft/pending_review/published/retired及版本/来源/命中与回退结果；模拟样本标记synthetic、编制批次和规则依据；样本存在不等于已审核上线。
- **权限/规则：** BR-CS-005～009、029～031、033、038、049；保留已确认权限与隐私边界，不修改旧工程或擅自新增项目。
- **验收：** AC-CS-009～012、045、048、072～073、088；FAQ复用与RAG召回/生成分开评价，命中FAQ不能冒充RAG链路通过。

### FR-CS-032 余额账户与业务流水

- **角色/触发：** 顾客查询本人余额/流水、确认购物付款，退款业务满足条件后入账。
- **前置与输入：** 服务端本人账户、币种、订单/支付/退款/充值关联和金额；开户初值0元，无预赠资金。
- **正常：** 开户记录0元初值，模拟充值/购物扣款/退款形成不可重复流水；顾客核对余额前后值与关联业务。测试样本需要非零余额时先执行模拟充值并保留来源。
- **异常/拒绝：** 余额不足不得支付、不得负余额、不得超额退款或入他人账户；重复/结果不明先核对；客服/主管/店铺管理员不能直接改余额，模拟充值见FR-CS-037。
- **输出/状态：** 余额、流水类型/方向、金额、关联业务和结果；前端余额不是权威账本。
- **权限/规则：** BR-CS-003、010、018～019、025、044、047；不接真实资金。
- **验收：** AC-CS-003、061、066、068、070、085。

### FR-CS-033 例外处置案例沉淀与检索（P1，Q23确认纳入V1）

- **角色/触发：** 人工完成例外问题处理，形成案例候选；模型遇到可能同类的新问题。
- **前置与输入：** 脱敏问题模式、案例名称/分类、前置状态、适用范围、核验依据、处理步骤、所需角色/确认、结果及来源；不能直接复制原会话明文。
- **正常：** 从已完成人工处理整理脱敏候选，由主管审核；发布后按条件和权限检索给主客服模型参考，显示内部来源与适用限制；新问题重新核查当前事实。
- **异常/拒绝：** 未审核/过期/冲突或不满足适用条件的案例不作为可执行依据；不能因相似度高复制上一顾客结果、授予退款审批权或越过发货/改址硬规则。
- **输出/状态：** draft/pending_review/published/retired/rejected 候选语义、版本、反馈；目标是减少重复人工工作，效果待测，不宣称已有自进化成绩。
- **权限/规则：** BR-CS-004、015、027、030、034、037、046；Q23确认V1范围及主管审核。
- **验收：** AC-CS-074；按审核、适用、隐私、过期和事实重新核验检查。

### FR-CS-034 企业私有处置Skill候选与发布（P1，Q23确认纳入V1）

- **角色/触发：** 同类有效案例积累，管理者希望形成可重复处置流程。

- **正常：** Agent归纳Skill候选，主管审核并回归通过后发布；Agent仅在匹配条件且获准范围内加载；保留来源案例、评测/使用结果、版本回退与停用。
- **异常/拒绝：** 草案不自动生效；不能自改线上代码、权限、业务规则或扩大工具白名单；证据不足继续澄清/人工；此 Skill 是业务 Agent 的处置知识，不是安装本机 Codex 技能。
- **输出/状态：** candidate/reviewing/published/retired/rolled_back、版本与回归评测结果；默认由主管发起归纳、Agent可推荐候选，不设达到案例数即自动发布的规则。
- **权限/规则：** BR-CS-015、028～030、034～035、037、046；Q23确认V1最小闭环。
- **验收：** AC-CS-075；草案隔离、审核、权限不提升、停用和回归可验证。

### FR-CS-035 会话检查点与恢复

- **角色/触发：** 澄清/待确认/中断、断线、服务重启、人工接管结束或重复恢复任务。
- **前置与输入：** 可信会话主体、任务/模型/契约版本、脱敏状态及权威业务结果；PostgreSQL checkpointer 仅为技术候选。
- **正常：** 恢复可继续的条件和进度；重新鉴权、检查接管状态、确认有效性和业务状态；人工结束自动切 Agent，但旧写动作不自动执行。
- **异常/拒绝：** 过期确认/已发货/权限变更/未知版本需重查或重新确认；业务成功但检查点未保存时先核对业务结果，不重复扣款/退款；连接断开不等于取消任务。
- **输出/状态：** 恢复后的任务、状态解释、结果核对与新确认；检查点不作为订单、余额、退款或工单权威记录。
- **权限/规则：** BR-CS-002～004、018～019、024～025、029～030、037。
- **验收：** AC-CS-008、031～033、047、053、071、076、080。

### FR-CS-036 运输异常工单与受控退款（P1）

- **角色/触发：** 本人订单运输中未收到货，顾客查询、催件、请求拦截或报告丢件。
- **前置与输入：** 本人订单、付款及可退额、包裹/轨迹/异常材料；顾客确认建单与退款诉求，客服具有有效分派关系。
- **正常：** 记录独立运输异常工单→获分派客服核验→核实拦截退回或丢件责任→受控退款入本人余额；争议/例外交主管，退款与工单及履约核验记录关联。
- **异常/拒绝：** 仅轨迹延迟、拦截申请或审核通过不自动证明可退款；拦截失败仍运输中，继续跟进或主管核验；无依据不直接退款、不要求虚假确认收货；重复/结果不明先核对。
- **输出/状态：** 待核验/待拦截/拦截失败/退回已核实/丢件责任已核实/待争议处理/退款处理中/已退款；工单结果、履约事实与退款状态分开，正式售后入口仍关闭。
- **权限/规则：** BR-CS-003～004、010、015、018～019、025、040、042、044；Agent可以核验辅助和建单，不能批准运输异常退款。
- **验收：** AC-CS-061、065、069、070、082～083。

### FR-CS-037 本人模拟充值（P1）

- **角色/触发：** 登录顾客在余额页面发起模拟充值。
- **前置与输入：** 可信本人账户和输入金额、请求标识；后端取得账户归属，界面标明模拟充值；CNY精确到分为细化默认，不采用原1～10000元业务限额建议。
- **正常：** 顾客输入金额→点击“模拟充值”确认本次金额→受控业务等额增加本人余额并保存充值记录/唯一流水→显示结果；无需充值审批或真实支付渠道流程，也不要求独立确认弹窗。
- **异常/拒绝：** 他人账户、非数字/非正数/不合货币精度拒绝；数值表示范围作为数据设计约束，不能伪称用户已批准业务限额；重复点击/响应丢失/重试核对同一结果，不重复入账；模型文本和浏览器余额不是充值事实。
- **输出/状态：** 本次充值金额、业务编号、新余额及关联流水；结果不明时可核对原请求。开户0元，实际余额由模拟充值、支付和退款共同计算；无提现/转账，不建设充值审批或真实支付状态管理页面。
- **权限/规则：** BR-CS-003、010、018～019、025、037、044、047；无真实支付网关，员工不得直接改余额或代顾客充值。
- **验收：** AC-CS-066、070、085。

## 7. 数据需求与概念字典

### 7.1 字典与样本覆盖要求

这是需求层的数据项清单，不是物理表结构。后续数据设计须对每个字段补齐业务定义、单位/精度/币种、必填或条件必填、枚举、来源、归属、权限、空值语义、时间及版本；不能从 ORM 或迁移工具反推遗漏需求。每条正常/异常流程至少映射到输入、状态改变、输出数据项和一个验收样本。

### 7.2 数据来源与样本要求

- 采用少量合成店铺数据，包含至少两个顾客、不同角色、多个SKU/购物车条目、未付/已付未发货/运输中/本人已确认收货订单、运输异常与退货退款、充值/退款/余额流水、Agent审核及案例/Skill版本；具体数量随样本清单评审，不缩减必需字段。
- 异常样本至少覆盖他人订单、无记录、缺字段、政策冲突/过期、余额不足、重复支付/退款、一次改址限制、改址/发货及取消/发货竞争、物流陈旧、人工接管迟到输出、服务重启和结果丢失。
- 真实 CSV 到位后登记来源/许可、字段/枚举/单位、订单与明细粒度、去重键、时间范围、缺失/异常/孤儿关联、金额平衡和身份映射。未核验的约38万订单/9.8万用户不作为此处样本规模或性能事实。
- 真实数据缺必要字段时，记录“原数据未含此项”及业务补录/合成扩展/其他来源；真实部分和合成补充可辨识，不伪装为原始字段。
- SQL 训练标注、客服业务验收集、案例归纳样本和 Skill 回归集分别版本化；测试集不能因被纳入案例库而继续声称独立未见。

### 7.3 关键状态与一致性

状态名称为需求语义，不锁定物理枚举。业务结果、人工会话与任务状态分别记录；已付未发货取消需Agent审核，发货后运输中、本人整单确认收货后才开放正式售后；运输异常和收退退款条件按Q19/020执行，未付款取消关闭为待评审默认。

| 对象 | 核心状态/转换 | 权威依据、拒绝与恢复 |
| --- | --- | --- |
| 订单 | 待付→已付未发货→运输中→顾客已确认收货；此后可申请售后，关闭为独立终态 | 发货事件进入运输中；本人确认收货才开放正式售后，承运签收不代替确认；取消/异常退款分别判断 |
| 支付/退款执行 | 发起→处理中→成功/失败；结果不明单独可观察 | 成功扣款/入账与业务状态一致；结果不明先核对，不重放导致二次扣/退 |
| 售后 | 本人确认收货后：申请→人工审核→批准/拒绝→待退货→店铺核验收退→退款处理→已退款 | 审核/填物流不提前到账；退货丢件争议由主管留依据处理；运输中走独立异常流程，量额不超可退 |
| 工单 | open→assigned→in_progress↔waiting_customer→resolved/closed；可重开 | 有当前有效负责人、公开结论与内部备注；改派后旧负责人新操作失效；关闭不删除历史 |
| 顾客会话/服务模式 | open/closed；open内agent→queued→human→agent | 点击结束人工后自动切Agent，关闭工单/连接断开不等于关顾客会话；迟到旧任务不覆盖当前模式 |
| Agent任务/确认 | accepted→running→awaiting_input/awaiting_confirmation→完成/拒绝/失败/结果不明 | 检查点只保存脱敏进度；恢复重新鉴权/查业务状态/确认有效性；人工恢复不自动执行旧写动作 |
| 知识发布/索引 | 草稿/校验→已发布→停用/过期；索引准备/可用/失败另记 | 发布状态不等于索引已就绪；撤销内容读取前检查；新版本切换和缓存失效有证据 |
| 案例/Skill | 候选→待审核→已发布→停用/回退；可驳回 | 主管审核、Skill回归通过及适用范围满足才生效；候选不自动上线或提升权限；Q23确认V1闭环 |
| 运输异常处理 | 工单待核验→待拦截/待责任核验→退回已核实/丢件责任已核实→退款处理；可拒绝或转争议 | 拦截失败不直接退款，主管例外留依据；不通过修改“已收货”来进入正式售后，退款与工单/付款/余额可对账 |
| 模拟充值 | 待确认→处理中→成功/失败/结果不明 | 本人顾客确认；同请求仅一次入账；结果不明可核对，不允许员工直接修改余额值 |
