## 2. 权威与边界

- 02生产：不可变运营方案、测算/资源检查、审批、执行任务、短期执行授权。

## 4. 方案执行授权样本（合成协议样本，不是已运行结果）

```json
{
  "contract_version": "XOPS-ACTIVITY-v0.1",
  "grant_ref": "grant_demo_001",
  "execution_intent_id": "intent_demo_001",
  "store_id": "store_demo",
  "actor_ref": "staff_demo",
  "auth_version": 3,
  "capability_revision": 5,
  "plan_ref": "plan_demo",
  "plan_version": 2,
  "approval_ref": "approval_demo",
  "manifest_digest": "sha256-of-canonical-manifest",
  "source_kind": "synthetic",
  "validation_scope": "selected_skus_in_stock_direct_price_v1",
  "issued_at": "2026-11-10T09:00:00+08:00",
  "expires_at": "2026-11-10T09:01:00+08:00",
  "activity": {
    "start_at": "2026-11-11T00:00:00+08:00",
    "end_at": "2026-11-12T00:00:00+08:00",
    "currency": "CNY",
    "promotion_budget_minor": "100000",
    "fixed_budget_allocated_minor": "10000",
    "items": [{
      "sku_id": "sku_demo_A",
      "expected_price_version": 4,
      "base_unit_price_minor": "10000",
      "activity_unit_price_minor": "9200",
      "quantity_cap": 100
    }]
  }
}
```

金额字段是上限与确认规则，不代表已支付费用或现实需求预测。样本manifest_digest是说明占位，不允许以该字符串做实现中的合法摘要。实际摘要覆盖全部关键字段，密钥/签名或固定认证通道、规范化格式需双方设计签收。真实发布用户必须是任务指定执行人或已记录的授权替代者。

审批版本唯一键为(store_id,plan_ref,plan_version,approval_ref)，两边均执行：01先持久创建唯一execution_slot/服务器intent，02只授一次grant；01活动同时对slot/grant唯一并存body摘要。同一审批即使换幂等键、双客户端或旧活动结束，也不能创建第二活动。失败终态也不重开；需新方案版本/人工审批，展示旧预算已核销与未付预占，明确批准新增预算或扣除旧占用。

发布临界区先锁主体/能力再锁slot，验grant未到期并受理后可完成本地事务；finalize-expired必须锁相同slot，等原事务提交/回滚后才能返committed或写closed_no_effect。在取得锁后验时钟，锁等待超时返回unknown。没有slot、查不到活动或过期本身不是无效果证明；只有持久closed_no_effect＋terminal_revision才可解除02冻结，迟到旧请求被该slot拒绝。

发布冻结的经营快照/成本/情景是有期限的批准假设：新数据标待重评，不允许02单方面作在途撤销承诺；01的权限/能力版本、基准价、可售、库存/额度与活动状态仍在本地临界区实时校验。撤销审批必须通过cancel-request同槽位屏障：先成功闭合才显示取消；已提交则返回活动由有权人员暂停/结束。修订草稿不覆盖原授权，不重新授同审批grant。

## 5. 活动/价格/额度语义

| 场景 | 规则 |
| --- | --- |
| 发布时间早于开始 | 活动已持久发布但phase=scheduled，不能显示已经享受折扣 |
| 生效时间 | 每次报价/建单按[start,end)与状态/修订/额度判断，可信时钟来源01 |
| 直降价格 | 0<活动价<基准价，整数分；基准价和price_version必须与审批/预检一致；没有优惠收益时保留原价方案，但不虚构降价活动 |
| 同SKU活动重叠 | 发布/恢复在SKU锁下检查，不支持叠加；冲突拒绝而不任意覆盖 |
| 有未结束活动时常规改价 | V1拒绝并要求先结束活动；不把活动结束当“恢复旧价”的盲写 |
| 库存/额度变化 | 建单事务内重查；quote不占额度，可能因竞争变为stale，须用户重报价，不自动全价下单 |
| 订单预占 | 使用01现有商品/SKU锁和库存预占，在同一事务预占活动qty与让利；固定费预算占用与变动让利分别记 |
| 付款/未付取消/过期 | 分别核销/释放同一reservation，幂等；活动暂停后已有订单不丢已承诺的价格 |
| 付款后退款 | 按订单原allocated/paid金额和原分摊退款；活动额度不自动回补，实际退款及经济影响另列 |
| 暂停/结束 | 新活动quote/建单停止；已有未付订单仍按原付款期限，已付订单不改；恢复须预检，结束不能恢复 |

不将“已确认可行”承诺为实际销量或利润保证。运行中超数量/让利预算是01硬门禁；经营利润低于监控阈值先提示并允许有权人员暂停，不让LLM修改交易价格或退款。

## 6. 错误与最小样本包

| 类别 | HTTP建议/处理 | 必测样本 |
| --- | --- | --- |
| unauthenticated / forbidden / not_found | 401/403/404；无权不泄露其他店；不重试 | 顾客/普通运营/跨店/撤权，伪造actor或服务身份 |
| invalid_input / unsupported_rule | 422；字段、币种、价格、窗口错误；不近似 | 非整数分、混币、负价、跨SKU券、缺任务/资源 |
| plan_not_ready / version_conflict / activity_overlap | 409；补数据/重算/新预检 | cost NULL、执行不支持、旧plan/SKU/activity、重叠窗 |
| budget_or_quota_exhausted / inventory_changed | 409；重新报价/补数 | 并发超1件/1分、库存变化，不静默全价 |
| grant_expired / contract_mismatch | 409/422；拒绝，不造字段或换版本重发 | 到期、未知版本/摘要、重复键不同body |
| timeout / unavailable / rate_limited | 504/503/429；有界重试/退避，写结果未知先对账 | 提交后断连、Outbox重放、服务重启、01暂不可达 |
| not_ready / partial / late | 经营快照用明确状态/错误，空与0分开 | 未生成、水位滞后、迟到退款、重复修订、历史过期 |

双方签收包至少含：正常草稿预检、确认后发布/回执、空经营快照、缺成本/资源、执行不支持、未知版本、错摘要、越权、重复幂等、写后超时、活动暂停/结束、两种修订到达顺序；附source_kind与金额单位。事件event_id强制必填、资源revision递增；客服旧契约required遗漏另行对齐，不传播到新执行契约。
