## 执行与口径

1. 原业务连接只执行服务端生成的单快照SELECT，不接受候选SQL；店铺来自每次在线身份，完整主键指定归档。
2. 验证归档digest、归档内部身份和结构，取 `visible=min(requested_as_of,snapshot.as_of,trusted_now)`。
3. 先按status=paid、`start<=paid_at<end`及`paid_at<=visible`筛选支付cohort；channel可选，采用strip后空转unknown的领域口径。零元paid仍计订单。
4. 独立内存库ops_order一单一行；ops_order_item保留原生数组line_no，同订单同SKU多行不去重，避免join扇出。金额/qty存精确整数字符串，SUM由SQLite登记的Python整数aggregate实现；不是SQLite浮点SUM或BIGINT SUM。金额结果字符串，订单数/件数JSON整数。
5. 严格小语法仅接受schema的三种SELECT（大小写/连续空白可变化），拒绝JOIN、GROUP BY、子查询、CTE、注释、多语句、字面值过滤、函数/字段/表越界。执行经校验的候选原文，通过SQLite真实aggregate取得结果；不调用固定指标工具冒充SQL。
6. 投影建好后开启query_only与SQLite authorizer（只许指定表READ/SELECT及sum/coalesce/count），关闭后即销毁。参数仅时间窗/as_of/SKU/channel，SQL绑定仅sku_id，其他筛选由后端投影执行。金额和订单数不允许SKU筛选悄然改口径。

## 预算与审计

每进程最多2个并发；不排队，超额429。最多20000订单/100000订单行/8MiB归档，SQL4096字节；SQLite max_page_count=8192,page_size=4096（32MiB页），输出最多1行/4096字节。隔离执行预算1000ms，Python阶段检查与SQLite progress_handler配合，超时408。预算包含归档读取后的检查和投影，但同步业务归档SELECT本身不能被此Python软截止抢占；真实PG查询/连接timeout仍沿原DB配置，不能宣称这是生产硬时延SLA。JSON解码/验证和内存复制受归档大小上界约束；不是操作系统级进程RSS硬配额。

单独JSONL审计目录默认02/data/query-audit，可用OPS_QUERY_AUDIT_DIR指定。保存请求关联、契约/SQL摘要、身份摘要和授权修订、归档/上下文摘要、行数、耗时与结果；不写SQL/参数/正文/Cookie/身份店铺明文。审计写失败停止返回结果503；业务库不新增审计行。此目录需部署者保证私有访问、容量轮转与持久存储，当前只做每日文件分区，不宣称已有全局日志留存服务。
