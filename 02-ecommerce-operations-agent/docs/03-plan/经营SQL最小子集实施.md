## 实现选择

- 沿用 FastAPI/SQLAlchemy 和现有 JSON 归档；新逻辑资源仅 ops_order、ops_order_item。
- 不在既有PG创建视图/表或改授权。02先用固定参数SELECT读取服务端店铺+snapshot_id+revision，核对归档摘要/版本；再创建单请求`:memory:` SQLite投影、实际执行候选SQL，执行后销毁。SQL语法为可用于PostgreSQL的三个基础聚合子集，**运行引擎明确为SQLite内存投影，不宣传成PG执行面**。
- 使用完整语法匹配的有限SQL校验器，仅三个指标及声明的聚合/表/参数/别名；不对任意SQL做关键词过滤。拒绝JOIN、子查询、算术、额外字段、写语句、多语句及注释。后续扩展语法需升级契约和反例，不把该子集等同任意经营SQL。
- 服务端先按现有paid状态、事件窗与visible筛出支付cohort。SQL不能省略WHERE来扩大店铺、修订、时间或SKU范围。金额使用精确整数SUM，防止SQLite隐式浮点/64位溢出。
- 审计写02独立有界JSONL，不写现有ops_audit或其他业务表；不自动轮转删除审计。审计不可用/写满失败关闭。
