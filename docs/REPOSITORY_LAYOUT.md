# 仓库结构与收录规则

本仓库以三个项目目录并列组织，保留现有导入路径与兄弟项目相对路径。没有移动业务代码、合并数据库或替换依赖。

| 位置 | 内容与维护方式 |
|---|---|
| 各项目 backend、frontend、training、sandbox | 源码、测试、锁文件及独立运行入口 |
| 各项目 contracts | 已实现接口和数据契约；草案或局部协议按项目说明区分 |
| 各项目 docs/01-requirements、02-design、03-plan | 需求、设计、计划与原始决策；历史文档不覆盖最新检查摘要 |
| 03/data/sft_v1 | 冻结合成样本、manifest、来源与审核侧车；train/dev/test 为152/12/20 |
| 根目录 docs | 当前跨项目状态、使用前提与发布边界 |
| 根目录 scripts | 面向 Git 索引的仓库检查；不启动业务或模型 |

## 仅留本机

以下文件通过忽略规则留在本机，不删除、不改写历史证据：

- `.runtime`、`.env`、私有凭据和本机进程登记。
- Python虚拟环境、node_modules、缓存、构建结果、数据库文件与集群目录。
- shared-models、模型权重、训练输出，以及03外部下载数据和生成中间集。
- 各项目 HANDOFF.MD、docs/07-iteration 和 docs/06-acceptance 中包含本机上下文的逐次验收归档。

这些本地记录不是可直接迁移的部署包。公开仓库用 [STATUS.md](STATUS.md)记录结论范围，不把本机密钥或旧运行身份作为复现前提。历史正文中指向本地归档的链接在 GitHub 上可能不可用；当前公开入口以三个项目 README 和本目录为准。

## 修改边界

01拥有顾客交易、履约、客服与业务权威记录；02拥有经营快照、方案与运营投影；03拥有数据、训练、推理与评测。跨工程接口修改须说明生产方、消费方、版本和验证范围。模型服务不代替业务鉴权，SQL候选不直接执行写操作。

独立依赖不合并为一个运行环境。03的评测沙箱使用自己的临时PostgreSQL，不连接01/02业务库。数据库初始化、真实模型调用和训练须在目标环境与授权范围确认后单独执行。
