## 1. 结论

- **26 例中 23 例判定一致（88.5%）**；03 对 26 例均符合预期；01 对 23 例符合预期。
- 3 例差异：`N05`（自连接）、`N13`（LIMIT 100）、`N18`（ORDER BY 参数）。01 均接受；03 均拒绝。
- 这 3 例不是 sqlglot 版本解析差异：两个版本都能解析；差异来自规则/重写。
- 01 会在接受后**重写 SQL**：加引号、加表别名、补 `LIMIT 20`、把 `LIMIT 100` 强制改成 `LIMIT 50`；03 只做校验，不重写（除参数渲染）。
- 01 的错误码高度聚合（多数 `unsafe_query`）；03 用细码（`unsafe_query/invalid_limit/invalid_parameters/...`）。联合契约不能只比较“是否接受”，必须比较**重写后 SQL、列名、参数集合、错误码**。
- 在双方未决定 N05/N13/N18 前，03 的训练/评测标签按**更严的 03 规则**生成；不把 01 的“接受/重写”当作 03 标签可直接执行。

## 3. SQL 重写差异

| 例 | 03 输出 | 01 输出 |
|---|---|---|
| P01 | `SELECT count(*) AS n FROM cs_order_self` | `SELECT COUNT(*) AS "n" FROM "cs_order_self" AS "cs_order_self" LIMIT 20` |
| P05 | 原 SQL（仅校验） | `SELECT DATE_TRUNC('DAY', "cs_order_self"."created_at") AS "d", COUNT(*) AS "n" ...` + `LIMIT 50` |
| N13 | reject `invalid_limit` | `... LIMIT 50`（不报错） |
| N18 | reject `invalid_parameters` | `... ORDER BY :order_id LIMIT 20`（不报错） |

含义：

- 01 的“通过”不等于 03 的“通过”；01 的“拒绝”也不等于 03 的细码。
- 01 的 `LIMIT 100 → 50` 是**静默重写**；评测若比较“是否截断”必须记录，不能只看结果。
- 03 的 `ORDER BY` 参数拒绝比 01 更严；若联合契约允许，需 01 在契约中明确“ORDER BY 参数”的语义，否则 03 继续拒绝。
- 01 的自连接接受可能是 01 的缺口；03 已列 `N05` 类反例，建议 01 补 `left.name == right.name` 且 alias 不同。

## 4. 错误码映射（对照用，不是联合契约）

| 03 码 | 01 码 | 场景 |
|---|---|---|
| `unsafe_query` | `unsafe_query` | 写/DDL/`SELECT *`/`CASE`/`CAST`/`LIKE`/危险函数/多语句（01 聚合） |
| `ambiguous_grain` | `ambiguous_grain` | 多表同层 `sum/avg` |
| `invalid_limit` | `unsafe_query` 或接受+改 50 | 超 50 / LIMIT 参数 |
| `invalid_parameters` | `unsafe_query` 或接受 | 未声明参数 / ORDER BY 参数 |
| `unapproved_function` | `unsafe_query` | 非白名单函数 |
| `unapproved_literal` | `unsafe_query` | 非枚举字符串 |
| `unapproved_resource` | `unsafe_query` | base table/schema 限定 |
| `sql_too_large/sql_too_complex` | `unsafe_query` | 字节/节点/join/CTE/深度超限 |
| `not_single_statement` | `unsafe_query` | 多语句 |

> 01 的码是消费者 API 的稳定返回；03 的细码用于训练/评测归因。联合契约应只承诺 01 的稳定码 + 可选 `detail`，03 不要求 01 复制细码。

## 5. 对数据冻结的影响

1. **合法 SQL 误拒**：P05 已修（`timestamp_trunc` 函数名）；当前 6 个正例全过。后续扩展正例必须同时跑两个 validator，任何“03 拒绝但 01 接受”先归因，不直接改标签。
2. **结果列名/类型**：01 会引用/重写列名并检查唯一性；03 只做唯一性检查，不强制引号/别名。评测比较需绑定“01 重写后的列名”，不能只比较值。
3. **参数**：01 的 `ORDER BY` 参数接受、`LIMIT` 参数拒绝；03 对所有非值位置参数拒绝。联合契约需明确参数只用于值位置。
4. **权限/错误判分**：01 的 `unsafe_query` 聚合多种原因，评测不能把“01 拒绝”当“业务语义错误”；03 细码用于归因，最终以 01 业务签收为准。
5. **版本**：01 要求 `sqlglot>=30.24.0`；03 沙箱当前 27.20.0。03 的 27.20 结果只证明 03 目标级行为；在升级并重跑前，不宣称与 01 等价。
