# 96GB 原生训练运行说明

> ITER-20261025-01：本轮只检查与修补，禁止开始任何训练（含 tiny 更新）。checkpoint 身份和评测协议已加强；本轮结果、兼容限制与待训练复验项见 `docs/07-iteration/ITER-20261025-01/review-output/`。以下 GPU 命令和清单留待后续授权。

目标：单卡 RTX PRO 6000 Blackwell 96GB，Qwen/Qwen3-8B-Base，SFT → GRPO。
本轮只实现代码和本地验证，不租卡、不下载 8B、不真实训练、不付费。旧 A100/QLoRA 选型不作为当前默认。

## 实现边界

PyTorch 负责 forward/loss/backward/梯度累积/optimizer.step/GRPO 更新；模型加载/tokenizer 允许 Transformers，优化器允许 torch.optim.AdamW。
原生 LoRA 注入冻结的基础线性层，默认 r=16/alpha=32/dropout=0.05，覆盖七类 attention/MLP 投影。
不使用 Trainer、TRL、Accelerate、DeepSpeed、verl、PEFT。BF16 默认避免 4bit 量化对 Blackwell 扩展的耦合。

权重粗算：8B×2 字节约 16GB（十进制），只包含基础权重，不含激活、logits、临时 tensor、LoRA 梯度和优化器状态。
GRPO 的 reference、group generation、completion 长度会增加成本，96GB 是否够用须短步实测。
梯度检查点与 SDPA 用于控制显存；默认不启用 torch.compile，先排除编译时间与架构差异。

## 参数入口

`training/configs/rtx_pro_6000_96gb.json` 是运行参数入口；`training/configs/smoke_cpu.json` 是微型模型调试配置。
模型路径默认 `/root/autodl-tmp/models/Qwen3-8B-Base`，`local_files_only=true` 禁止运行时自动下载。
配置可复制为实验文件或通过重复 `--set key=value` 覆盖；输出必须保存最终生效配置。
CPU 配置需要本地创建 tiny 模型；SFT 1152、prompt 1024 保留真实 schema 长度，但 8 token completion 只测流程。
SFT 的 fused_adamw/pin_memory 在 GPU 默认开启、CPU 关闭；length_bucket_size=32、loss_chunk_tokens=32。
仅对答案尾段投影词表，减少 prompt logits；CE 分块减少 FP32 工作区，bucket 减少 padding；是否提速与峰值降低须 GPU 测量。
GRPO 共用冻结底座，只额外保存 SFT 参考 LoRA；整组 old/reference 从 2×G 次前向缩为两次，current 按单候选反传。
GRPO 的 old/current/reference 使用相同温度；本版要求 top_p=1、top_k=0 以匹配实际采样分布。GRPO 支持 BF16/FP32，FP16 明确拒绝。

| 参数 | 当前默认 | 含义 |
|---|---|---|
| SFT batch / accumulation / max_seq_len | 1 / 8 / 1152 | 单卡有效每步 8 样本；尾批语义见训练代码 |
| SFT lr / max_steps | 2e-4 / 60 | 工程首跑上限，尚未验证最优性 |
| GRPO batch / accumulation / group | 1 / 4 / 4 | 每题四候选，token/时间成本须实测 |
| GRPO prompt / completion | 1024 / 160 | 限制生成与反向长度 |
| GRPO lr / beta / clip | 5e-6 / 0.04 / 0.2 | reference KL 与 clipping 配置 |
| min_vram_gb / min_disk_gb | 90 / 80 | 检查器按 GiB 比较当前空闲资源 |
| max_seconds / pipeline timeout | 14400 / 14400 | 阶段预算 / 整次流水线共享预算；实例人工停机 |

96GB 标称容量不能证明训练峰值。其他进程会改变空闲显存，训练后须记录实际峰值。

## 环境与命令

依赖为 Python 3.11、torch 2.7.1+cu128、transformers 4.51.3。官方提供 cu128 wheel 与 Qwen3 模型代码；这不意味着本机安装或 GPU 实测。
依据：[官方历史安装版本](https://pytorch.org/get-started/previous-versions/)、[2.7 Blackwell/CUDA12.8 公告](https://pytorch.org/blog/pytorch-2-7/)、[Qwen3 4.51.3 源码](https://github.com/huggingface/transformers/blob/v4.51.3/src/transformers/models/qwen3/modeling_qwen3.py)。
Context7 检索的 PyTorch 兼容矩阵将 2.7 的 CUDA12.8 列为 experimental；保留 GPU 内核短测作为验收项。

从 03 根目录按 `training/README.md` 手动创建 venv、安装，再运行：

```bash
python training/check_environment.py --config training/configs/rtx_pro_6000_96gb.json --offline
python -m training.pipeline --config training/configs/rtx_pro_6000_96gb.json --dry-run
```

检查器不加载权重、不联网、不启动训练、不创建模型目录；JSON 记录通过/待补/跳过及限制。
导入检查器不导入 torch/transformers。运行时允许导入 torch 查询驱动、设备和包版本。
文件检查是结构完整性检查，不能代替来源 revision/hash 核验；SDPA 只检查 API 存在，不宣称内核运行成功。
