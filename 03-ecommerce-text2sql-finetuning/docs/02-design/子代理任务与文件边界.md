## 2. 文件锁与并发规则

- 最终文档由主执行独占写入：`HANDOFF.MD`、`docs/01-requirements/PRD.md`、`docs/01-requirements/需求评审记录.md`、`docs/01-requirements/需求追踪与验收矩阵.md`、`docs/02-design/*.md`（不含 `_research/`）。
- 子代理只能写自己名下的 `_research/*.md`；不得改其他子代理文件、不得改 01/02、不得改根目录配置。
- 同一文件同一时间只允许一个写入者；主执行在集成前不修改 `_research/` 内容，只做事实复核与引用。
- 子代理不得执行：训练、下载模型、租卡、付费 API、01/02 的 reset/prepare/迁移/fixture、数据库写入。

## 3. 证据标准

1. 每个关键结论至少一个可定位证据：URL + commit，或本地 `文件:行`。
2. 区分“仓库当前实现”“README 声称”“我的推断”；推断必须标注。
3. 价格、显存、版本、许可证等易变事实必须带抓取/核对时间。
4. 不得把公开数据或参考项目的表名/口径直接映射成本项目金标；业务金标必须匹配 01/02 获准契约。
5. 失败/不可访问要记录原因与已尝试路径，不用猜测补齐。

## 4. 集成与归属

- 主执行逐份复核：抽查关键文件/行、复算价格或版本、核对与 01/02 源码的一致性。
- 采纳内容进入 `docs/02-design/参考项目复用与修改清单.md`、`数据适配方案.md`、`质量验收方案.md`、`显卡选型建议.md`；未采纳内容保留在 `_research/` 并注明原因。
- `HANDOFF.MD` 记录子代理 ID、任务、产出文件、复核结论、贡献归属；不把子代理产出直接当最终结论。
- 数据质量仍由 Codex 独立检验；子代理不生成/审核最终金标。
