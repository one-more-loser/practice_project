## 1. 结论

1. **SQL-R1** 的“SFT 冷启动 → GRPO → 执行结果奖励”路线与我们的 SFT→GRPO 方向一致，可复用其**训练阶段划分、奖励分层思想、候选选择/评测思路**；但其官方训练栈要求 **8×80GB GPU + verl/vLLM**，单卡 AutoDL 不能原样复现。其格式/长度奖励不能照搬，否则会奖励“更长/更会格式化”而不是业务正确。
2. **XiYan-SQLTraining** 是 **SFT-only** 数据/训练流水线，不含 GRPO；可复用 **M-Schema 表示、SFT 数据组装、EX 结果等价评测**；其依赖（`transformers==4.42.3`）、Qwen2.5-Coder 模板、`max_new_tokens=10`、直接 `cursor.execute`、mask 逻辑等**必须重写/重验**，不能直接用于 Qwen3-8B-Base。
3. 两个参考项目都面向 **Spider/BIRD 通用 benchmark**，不是 01/02 的业务 Schema/指标/权限/澄清契约；业务能力必须用本项目数据训练与评测。公开数据只补通用 SQL 语法/结构，不映射 `cs_*`/`ops_*` 表。
4. 单卡可行性尚未实测：8B + GRPO 的显存/吞吐是**待验证假设**，不是承诺。若单卡无法在预算内完成有效 GRPO，应如实报告并停在 SFT 或缩规模，不用 reward 上涨冒充达标。

## 3. SQL-R1：可复用与必须重写

### 3.1 已核实事实

| 项 | 事实 | 证据 |
|---|---|---|
| 路线 | SFT 冷启动 → GRPO；RL 数据为 SynSQL-Complex-5K（复杂样本） | README/论文 §2.3 |
| 底座 | Qwen2.5-Coder-3B/7B/14B-Instruct | README 模型表 |
| 训练资源 | 官方要求 **8×80GB+ GPU**；推理 2×40GB | README Environment |
| 训练栈 | Python 3.9+、CUDA 12.0+、torch 2.4.0、vllm 0.6.3、verl、flash-attn | README |
| 奖励 | Format ±1；Execution +2/0/−2；Result +3/0/−3；Length 仅在结果正确时给，含 `0.5*Stl+Sal`，超长惩罚 | 论文 §2.3.3 式(2)–(5) |
| 推理 | 生成多个 SQL 候选，执行后按 self-consistency 选最高分 | 论文 §2.4 |
| 结果 | Spider 88.6%、BIRD 67.1%（论文自报，不是本项目成绩） | README/论文 |

### 3.2 可复用

- **阶段划分**：先 SFT 冷启动，再 GRPO；GRPO 从明确 SFT checkpoint 继续。
- **奖励分层**：格式、可执行、结果正确分层；执行失败不进入结果奖励。
- **候选选择**：推理时多候选 + 执行/结果投票，可作为服务层候选选择参考（是否启用待设计）。
- **评测思路**：执行结果等价（EX）而非 SQL 文本匹配；与我们的多 fixture 结果等价方向一致。

### 3.3 必须按本项目重写

| 点 | 原因 | 本项目做法 |
|---|---|---|
| 底座 | 参考用 Qwen2.5-Coder-Instruct；本项目固定 Qwen3-8B-Base | 重新做 Base 基线、SFT 模板、tokenizer/EOS、loss mask |
| 训练栈 | verl/vLLM 8×80GB，单卡不可原样跑 | 先做单卡 LoRA/QLoRA + 轻量 GRPO 可行性小试；框架选型待设计评审 |
| 奖励 | Format/Length 可被“更长/更格式”利用；Result 只看 EX，可能放过口径错/恒空 | 格式/安全作为门控；语义/结果为主；长度奖励默认关闭或仅作极小辅助且不得抵消错误；增加契约/澄清/未知值/反作弊分量 |
| 数据 | SynSQL 通用 schema，无 01/02 业务语义 | 业务数据 + 公开通用数据分层；样本绑定 profile/Schema/指标/参数 |
| 权限/安全 | 参考直连数据库执行，无 01 validator/RLS/只读约束 | 03 隔离沙箱 + 只读/资源/字段限制；业务库不直连 |
| 资源 | 8×80GB 不是单卡预算 | 单卡 24/48/80GB 方案分别估算；GRPO 规模/G/长度可缩，但不保证等效 |

### 3.4 明确不复用

- 不复制 SQL-R1 权重、SynSQL 数据、Spider/BIRD 成绩作为本项目基线。
- 不复制其 8×80GB 训练配置到单卡；不把“参考项目能跑”当“本项目能跑”。
- 不把 `<think>/<answer>` 格式硬套到 Base 模型；输出契约以本项目设计为准（JSON 四类响应）。

## 4. XiYan-SQLTraining：可复用与必须重写

### 4.1 已核实事实

| 项 | 事实 | 证据 |
|---|---|---|
| 范围 | SFT 数据构建 + 训练 + 推理/评测；**无 GRPO** | 子代理 B 报告；仓库 |
| 数据 | M-Schema + NL-SQL 对；支持多库/多方言 | 子代理 B 报告 |
| 依赖 | `transformers==4.42.3` 等旧版本 | 子代理 B 报告 |
| 关键缺陷 | Qwen3 Base 无 chat_template；`max_new_tokens=10` 会截断；直接 `cursor.execute` 无只读/超时；loss mask 只 mask padding；采样含 PII 风险 | 子代理 B 报告 |
| 评测 | EX（执行结果等价），可参考 | 子代理 B 报告 |
| 许可证 | Apache-2.0；BIRD 子集另有上游许可 | 仓库 `LICENSE` |

### 4.2 可复用

- **M-Schema**：把表/列/类型/主外键/枚举/描述组织成模型输入；我们改为“获准逻辑 Schema + 指标 + 参数约束”的稳定序列化，不暴露物理库/凭据。
- **SFT 数据组装**：问题 + schema + SQL 的样本结构；我们扩展为数据包字段（profile/修订/参数/响应类型/fixture/断言）。
- **EX 评测**：结果多重集比较；我们加列/排序/NULL/金额/时区/重复行规则，并补契约/安全/澄清判定。
- **训练脚本结构**：数据加载、collator、checkpoint 保存的工程骨架可借鉴，但依赖/模板重写。

### 4.3 必须重写/重验

| 点 | 原因 | 本项目做法 |
|---|---|---|
| `transformers==4.42.3` | 不支持 Qwen3 架构/模板；锁旧版会阻碍 | 选支持 Qwen3 的版本，锁实际验证版本；不盲目升级全部依赖 |
| chat_template | Base 无模板；Instruct 模板不适用 | 自建并冻结 prompt 序列化；训练/推理一致；验证 EOS/特殊 token |
| `max_new_tokens=10` | 只能生成极短 SQL | 按数据长度分布设上限；记录截断率 |
| 直接 `cursor.execute` | 无只读/超时/行数/成本限制 | 03 隔离沙箱 + validator + 资源限制；业务库不直连 |
| loss mask | 只 mask padding，可能训练到 schema/问题 token | 只对 assistant SQL/JSON 计算 loss；验证 mask 覆盖 |
| 数据采样 | 可能含 PII/敏感值 | 脱敏/过滤；日志与样本不含密钥/个人数据 |
| 切分 | 无去重/防泄漏 | 模板/来源分组；同义改写跨集检查；冻结测试 |
| 模型 | Qwen2.5-Coder | Qwen3-8B-Base；重做 Base 基线 |

### 4.4 明确不复用

- 不复制 BIRD/Spider 数据及其许可受限文件。
- 不把 XiYan 的 SFT 成绩当本项目 Base/SFT 成绩。
- 不沿用其旧依赖栈到生产训练；不以“能跑通”代替 Qwen3 兼容性验证。

## 5. 本项目适配方案（草案）

### 5.1 数据流水线

```
业务契约/指标/参数
  → 问题族模板（01/02 分离）
  → 业务样本（问题+profile+schema/metric revision+参数+响应类型+SQL/澄清标签+fixture+断言）
  → 公开通用样本（Codex 筛选，source_type=public-general，不映射业务表）
  → 缺口候选（03 生成，Codex 独立检验）
  → 去重/切分（模板/来源分组，防同义改写泄漏）
  → SFT 数据 / GRPO 题库（共享训练任务，不共享验证/测试答案）
```

### 5.2 训练流水线

1. **Base 基线**：Qwen3-8B-Base，冻结 prompt/解析器/测试集；记录零样本/少样本。
2. **SFT**：全参/LoRA/QLoRA 由 GPU 小试定；先 20–30 题过拟合小试，验证能学、能解析、有正确 SQL 候选。
3. **GRPO**：从明确 SFT checkpoint；先奖励验证 + 小规模 rollout；再正式训练。
4. **评测**：同一冻结协议比较 Base/SFT/SFT+GRPO；EX + 契约 + 安全 + 澄清/不支持 + 反作弊。

### 5.3 单卡资源含义（未实测）

- SQL-R1 的 8×80GB 是参考项目的训练配置，不是本项目承诺；单卡 24GB 只能考虑 QLoRA/短上下文/小 GRPO 规模，48GB 可放宽，80GB 可做更大规模但仍是单卡吞吐瓶颈。
- 具体选型/费用见 `显卡选型建议.md`；在实测前不承诺“8B 一定能在某卡训练”。
