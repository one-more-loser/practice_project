## 1. 数据长度与配置

真实 Qwen3-8B-Base tokenizer 实测（只下载 tokenizer/config，未下载权重；`outputs/sft-v1-tokenizer.json`）：184 条 prompt 860–990、answer 14–75、total **902–1051**、均值 951.55；`max_seq_len=1152` 时 0 超长、0 label 失败，EOS `<|endoftext|>` id 151643；实际 tokenizer `has_chat_template=true`，训练仍用自建纯文本 prompt。

| 参数 | 首跑值 | 说明 |
|---|---|---|
| 量化 | QLoRA 4-bit NF4，double quant | 24–40GB 单卡可跑；不是全参 |
| LoRA | r=16，alpha=32，dropout=0.05 | q/k/v/o/gate/up/down |
| batch | 1 × grad_accum 8 | 有效 batch 8 |
| 学习率 | 2e-4，cosine，warmup 3% | QLoRA 常用起点 |
| 步数 | **`max_steps=60`（本轮实际步数）**；epochs=5 仅为上限 | 数据 152 条，有效 batch 8，约 19 step/epoch；60 步不会跑满 5 epoch，足以验证真实更新，不足以证明泛化 |
| 序列 | 1152 | 184 条实测 total ≤1051；超长直接失败，不静默截断 |
| 精度 | bf16 compute | 由 GPU 支持决定 |

## 2. 显卡选择与显存依据

| 角色 | 机型 | 显存 | 判断 |
|---|---|---|---|
| **首选** | AutoDL `A100-PCIE-40GB` | 40GB | 8B 4-bit 权重约 5–6GB；LoRA 参数/优化器/激活/1k 序列留余量；可跑 Base 评测 + SFT；风险最低 |
| 备选 | `RTX 4090/4090D` 24GB | 24GB | QLoRA 可试；1k 序列 + eval 可能 OOM；GRPO 不建议；只作低成本备选 |
| 大显存 | `A800-80GB` | 80GB | 若 40GB 实测 OOM 或需更大 batch；单价更高，首跑不默认 |

显存数字是**保守估算，不是实测**：8B bf16 权重约 16GB；4-bit 约 5–6GB；LoRA 可训练参数约 20–40M；1k 序列 activations 与 KV 随 batch 增长。A100-40GB 的 40GB 比 24GB 更适合“Base 评测 + SFT + 失败重试”同机完成。

## 4. 一次性执行清单（确认后）

1. 租 1 张 A100-40GB，选数据盘 ≥50GB；记录实例 ID、镜像、驱动、`nvidia-smi`、`torch.version.cuda`（不把驱动 CUDA 上限当运行时）。
2. 建独立 venv；`pip install -r training/requirements-train.txt`；不升级 torch/CUDA。
3. 下载 `Qwen/Qwen3-8B-Base` 到数据盘（ModelScope/HF 任一可达源）；记录 commit/revision、tokenizer、许可证；校验文件数与大小。
4. 上传/同步 03 的 `data/sft`、`training`；校验 manifest SHA-256。
5. 先跑 `train_sft.py --dry-run` 与 `check_tokenizer.py`（目标 tokenizer 已在本机实测 902–1051 token；GPU 上复核）。
6. **Base 评测**：`eval_sft.py --model ... --load-in-4bit --max-seq-len 1152`，test 20 条，保存 `outputs/eval-base.json`。
7. **SFT**：`train_sft.py --qlora ... --max-seq-len 1152 --max-steps 60`；保存 adapter、tokenizer、`run.json`、Trainer 日志；记录步数、loss、显存峰值、吞吐。
8. **重载验证**：新进程加载 Base + adapter，跑一条固定问题，确认不是只保存了空 adapter。
9. **SFT 评测**：同一 test、同一 prompt、同一解码参数，保存 `outputs/eval-sft.json`；再跑 `eval_business.py`，用 01 validator + 03 PG oracle 逐条判定。
10. 导出必要产物到 03 获准位置；停止实例；核对账单与退出码；未达标如实报告。

## 5. 首跑判定（工程，不是最终业务验收）

- 必须：真实加载指定 Base；发生参数更新（step>0、loss 有记录）；adapter 可重新加载；Base/SFT 使用同一 test；日志/命令/版本/哈希可复核。
- 不必须：SFT 一定涨点。效果未提升时保留 Base 与 SFT 两份结果并分析，不调测试答案。
- 不声明：01/02 接入完成、RLS 已通过、80+40 消费集通过、GRPO 完成。

## 6. 风险与停止条件

| 风险 | 处理 |
|---|---|
| 24GB OOM | 换 A100-40GB；不盲目减 max_len 到失去语义 |
| 40GB 仍 OOM | 降 batch/seq、开 gradient checkpointing；仍失败则停，报告实测 |
| 下载慢/磁盘不足 | 只下一份底座，缓存放数据盘；不写系统盘 |
| 费用超上限 | 立即停机，保留日志，报告已完成步骤 |
| loss 不降/输出不可解析 | 先查模板、mask、EOS、标签；不延长训练掩盖 |
| 评测无提升 | 如实记录；先检查数据/模板/解码，再决定是否调参 |
