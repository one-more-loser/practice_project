## 5. 03 拟采用的 SQL-MODEL-v0.2 骨架

```json
{
  "request_id": "sql_req_...",
  "profile": "customer_self | operations_store",
  "question": "去身份化问题",
  "context": {"now": "...", "timezone": "Asia/Shanghai", "resolved_slots": {}},
  "schema_revision": "...",
  "schema_digest": "...",
  "metric_revision": "...",
  "snapshot_ref": {"snapshot_id": "...", "revision": 3, "digest": "...", "evaluation_as_of": "..."},
  "parameters": {"start_at": "timestamptz", "end_at": "timestamptz", "order_id": "text"},
  "limits": {"max_rows": 50, "read_only": true}
}
```

响应四类互斥：

- `query`：`sql`、`parameter_names`、`service`、修订字段；
- `clarify`：`slots[]`（可带 options）、`service`；
- `unsupported`：`reason_code`（如 `capability_unavailable`）、`service`；
- `error`：`code`、`retryable`、`service`。

**不采用**：`consumer_profile`、`parameters` 描述数组、`service_revision`、顶层 `reason_code` 与嵌套字段混写；这些由 01/02 适配层映射。

## 7. 结论

1. 01 的**现状能力**可按 52 列/四指标/直接执行器语义做 03 小闭环；**不能**据此说客服端到端接通。
2. 02 的**指标语义与权限边界**可作数据规范参考；**四投影/SQL 执行面/as_of 重放未实现**，不纳入正式训练。
3. 协议差异由 01/02 适配层处理，03 不要求两边同时改；共同契约仍需三方确认。
4. 03 独立 PG 结果只证明“合成 fixture 上的候选/校验/执行/断言”，不证明 01 生产库、02 SQL 面或模型能力。
